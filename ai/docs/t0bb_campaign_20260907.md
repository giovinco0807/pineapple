# T0-BB 戦役: 高精度教師ラベルで再訓練 (2026-09-07 開始)

オーナー指示: 「その前にT0bbで同様に高精度の教師ラベルを作ってモデルを学習させましょう」。
T0-BTN 戦役(`t0btn_campaign_20260902.md`)で検証した審判レシピを、そのまま BB の開始手に移す。
強さの物差しは 9/7 の裁定どおり **レース審判集合に対する 1決定あたり regret**(`referee-is-the-strength-metric`)。

## 1. BB が BTN と違うところ

| | T0-BTN | T0-BB |
|---|---|---|
| 入力 | 自分の5枚 + BB の配置済み盤面 | **自分の5枚だけ**(先手、何も見えない。`t0_bb_opponent_block_20260824.md`) |
| 根の分布 | チャンピオンのトレース(相手盤面が要る) | **54枚からの一様な5枚配札**。トレース不要 |
| 配信の柵 | ランカー上位 K=16 | **T0方策(policy.bin、54→243)の上位 8** |
| 配信の手 | トレースの実手(joint 標本に依存) | 監査の柵内 argmax そのもの(決定的) |
| 評価器 | `hu/t0_btn.bin` 207次元 | `hu/t0_bb.bin` 207次元(相手ブロックは空) |

BB の根には相手が無いので、`served` はトレースではなく「配信が選ぶ手」(方策上位8の中の評価器最良)を
ラベル生成器が自分で名付ける(`t0_btn_label.py --seat bb --serve-top 8`)。

## 3. ラベルのレシピ

- 場: 方策上位 16 ∪ served(`--field fence --ranker-top 16`)。配信は 8 だが、BTN と同じく K を後から掃引できるよう 16。
- 採点: `own_fl`(相手の FL クレジット除去)。
- fit/dev: 段階予算 **128:8, 500:3, 1400:1**(約 10,200 本/局面、平坦 316×16 の 2倍)。
  T0-BTN の dev 20 局面で平坦 0.590 → 段階2倍 0.366 の regret 改善(§12.16)。
- eval: レース(batch 64, floor 128, z=3, cap 8,192, target_se 0.35)。BTN では平均 23,409 本/局面、最善値 SE 0.42。
- 審判の継続手はチャンピオン(`models_ship_20260904`)、バイナリは binstamp 20260905a(Parts 対応)、
  ソースは `hu_src_20260907a.tar.gz`(BB 対応のラベル生成器)。

ローカル検証: eval 3 局面(平坦 32 本、段階 16:8,32:3,64:1)で生成 → `build_t0_btn_sharp --seat bb --encode-all`
で符号化、`t0_bb.bin` との parity 最大 6.7e-6(全 232 手 696 行)、ラベル行 4.3e-6。

## 6. 投入直後の欠陥: BB でジョーカー「X2」の根が全滅 (2026-09-07)

第1波の部分回収で、ジョーカー手の根がすべて `16 unknown keys (of 232 candidates)` で失敗、
ジョーカー無しの根は正常。原因は綴り: `--rollouts 0` の列挙は配札どおり `X2` で手を綴るが、
審判(`--hu-t0-deep`)はヒーローのジョーカーを位置で `X1` から振り直す。BTN(`--hu-t0-seat 1`)には
9/2 に入れた respell があり、レース480 でも X2 の根 122 行が正常だったが、**BB(席0)の経路には無い**。

修正はラベル生成器側(`canonical_jokers`: 入力の札を先に X1, X2 に振り直す。両経路が同じ綴りになる)。
Rust の再ビルド不要。ローカルで `bb/eval/0479`(X2)を通し確認。ソース `hu_src_20260907b.tar.gz`。

対処: 第1波(69台)はジョーカー無しの根(fit 約1,450・dev 約165・eval 240)を続行させ、完走後に
各シャードの GCS オブジェクトから error 行を取り除いて同じシャードを 20260907b で再投入(`--skip-done` が
ok 行の id を飛ばし、ジョーカー根だけ打ち直す)。error 行を残すと id が「済み」扱いになり再ラベルされない
(`measurement-traps` #9 と同じ罠)。

## 6. 経過 (2026-09-08 19:30 JST 時点、暫定)

**艦隊の実績**: 1局面あたり実測 27 分(見積 19 分)、Spot プリエンプト延べ 30 回超(すべて id 再開で回収)。
ジョーカー綴り「X2」の欠陥で第1波の該当根が失敗 → 修正ソース `hu_src_20260907b` で補充。
費用は延べ約 1,300 VM 時間 ≈ **$300〜330**(見込み $230 を超過。理由: 1局面の遅さ 4割と再起動)。
回収方法の教訓は `gcp-fleet-two-silent-failures` 3件目(流し読み1回、rsync/ワイルドカード cp 禁止)。

**訓練**: fit 1,800 + dev 187(2パス)で符号化(parity 9.5e-6)、`t0_bb.bin` から初期化、lr 1e-4、regret 選抜、3 シード。
dev の場内 regret(ラベル雑音込み): 学習前 0.414 → **0.249〜0.254**(3 シード一致、雑音 SE 0.03)。

**暫定採点**(eval 472/480 のうち符号化済み 456 局面、レース審判、1決定あたり):

| モデル | 柵 K=8(配信) | K=12 | K=16 | 対出荷 (K=8, ±局面) |
|---|---|---|---|---|
| 出荷 `t0_bb.bin` | 0.341 | 0.288 | 0.286 | — |
| s06 | 0.320 | 0.294 | 0.289 | +0.021 ±0.035 |

読み: BB の出荷モデルの取りこぼしは BTN(0.706)の半分以下。再訓練の利得は +0.04/決定(1.2σ、未決着)。
**柵 K=8→12 は訓練なしで +0.053 ±0.026(2σ)**、K=4 なら −0.27。K=12 以上は平坦。
最終値は eval 480 揃い次第 §7 に。

## 7. 最終採点 (2026-09-09 00:30 JST、eval 480/480 局面)

`t0_btn_race_audit --fence-by policy_rank`、レース審判(最善値 SE 平均 0.43)、1決定あたり regret:

| モデル | K=8(配信) | K=12 | K=16 | 対出荷 K=8 (±局面) | top1 (K=8) |
|---|---|---|---|---|---|
| 出荷 `t0_bb.bin`(=実戦の手) | 0.346 | 0.306 | 0.310 | — | 311/480 |
| s06 | 0.325 | 0.311 | 0.306 | +0.021 ±0.033 | 322 |
| s07 | 0.311 | 0.296 | 0.289 | +0.036 ±0.032 | 325 |
| s08 | **0.304** | **0.290** | 0.289 | **+0.043 ±0.031** (1.4σ) | 329 |

柵だけ(出荷モデルのまま): K=8→12 で **+0.041 ±0.026**(1.6σ)、K=16 で +0.036 ±0.032。K=4 は −0.27。
両方(s08 @ K=12): 0.346 → 0.290、+0.056/決定。(475局面の暫定値からの変化は小数第3位のみ。)測定雑音は 0.011〜0.014 で、残る不確かさは局面のばらつき。

**判定**:
- BB の出荷モデルは BTN の半分以下の取りこぼしで、伸びしろ自体が小さい。再訓練 +0.04、柵 +0.04、合計 +0.06/決定 ≈ +0.03/deal。
- 単独ではどれも 3σ に届かない(480 局面の分解能 ±0.06 と同じ結論)。BTN と同じく「向きは一貫、大きさは境界」。
- 効くのはジョーカー無しの手だけ(§6 層別)。ジョーカー手 0.38 は再訓練でも柵でも動かない → 別の手段が要る。

**選択肢**: (a) 柵 K=12 + s08 を対戦ゲート 40k ディール($24)で実利確認、(b) ジョーカー手だけの fit(例 1,000 局面、~$100)で
再訓練し eval のジョーカー層で測る、(c) T1 以降へ移る。費用対効果は (c) > (b) > (a) と見る(利得の絶対量が小さい)。
