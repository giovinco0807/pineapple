# T0 ランカー・アブレーション: 絞り込みは損失ではなく利得だった (2026-08-23)

「T0のモデルをさらに強くしたい」から始めた調査。診断は配信側のランカーを
最大の漏れと指したが、**対戦は符号ごと否定した**。忠実度→対戦の断絶、5例目。
今回は転写しなかっただけでなく**向きが逆**だった。

---

## 1. 判定

**出荷構成(T0を top-4 に絞る)が、絞らない構成に確定的に勝つ。**

ミラー、2シードセット、rankers/own_lap4/topk/joint-samples は完全同一。
違いは **アームBの T0 ランカー2枠を `none`** にした一点だけ
(`pair_up` は両席揃った街だけ `Some([bb,btn])` にするので、これで T0 の
shortlist だけが外れ、`hu_match` は `_ => candidates` に落ちて232候補すべてを
評価器に通す)。

| セット | 出荷(top-4)優位 | 95% CI |
|---|---|---|
| rk1 (seed 91000001) | +0.924 | [+0.612, +1.233] |
| rk1b (seed 92000001) | +1.347 | [+1.044, +1.663] |
| **プール 12,000ディール** | **+1.136** | **[+0.916, +1.350]** |
| プール・FL価値ゼロ採点 | +0.320 | [+0.230, +0.410] |

比較のため: lap2 全体(8スロット入れ替え)が **+0.325**、T3街の有効化が **+0.286**。
**絞り込みはその3.5倍の価値を持つ。**

## 2. なぜ「recall 42%」が損失を意味しなかったか

事前の診断(read-only プローブ)はラベル空間で次を測っていた:

- top-4 に教師の1位が残る率 **42.0%(BB)/ 57.1%(BTN)**、T1-T3 は 84〜89%
- shortlist の「天井」 1.9243(BB)/ 0.7043(BTN)
- lap2 の改善の 60〜76% が top-4 経由で消える

数字自体は再現されている。**が、失われているものが「価値」ではなかった。**
対戦の副指標がそれを示す:

| | 出荷(絞る) | 絞らない |
|---|---|---|
| ファウル率 | 26.4 / 25.8% | **23.8 / 23.9%** |
| FL入場率 | **31.6 / 32.5%** | 28.7 / 28.3% |
| 完全一致ディール | — | 41.9%(両セット) |

絞らないアームは**ファウルを2.5pt下げたのに、FL入場を3.5pt落として負けた**。
232候補すべてを評価器に通すと評価器は安全側を選び、FLを狙う開局が減る。
**ランカーは「悪い手を落とすフィルタ」ではなく、実質的に FL 志向の事前分布として
働いている。** 教師ラベルとの一致率で測ると、この働きは丸ごと「誤り」に見える。

**教訓**: 部品を「正解との一致率」で採点すると、その部品が担っている
**目的関数上の役割**が見えない。ランカーの仕事は教師の1位を通すことではなかった。

## 3. 測定の作り方(再利用のため)

- **`launch_verdict.sh` ではこの実験は書けない。** 同スクリプトは
  `RK=$(bins "$A" rankers)` として**両アームに同一のランカーを渡す**
  (コメントに「評価器のみの比較にするため」と明記)。したがって
  **これまでの全ミラーでランカーの寄与は common-mode で相殺されていた。**
  本件のランチャは `scratchpad/backfill_ranker.py` に埋め込んだ形が残る。
- **課金前にローカル20ディールで機構を実証した**: 厳密ゼロでないこと
  (= 設定が読まれていること)を確認。一致率50%、14.7秒/ディール。
  異なる設定で厳密ゼロなら「モデルが読まれていない」印(正典doc §10)。
- 単価は通常ミラーの約4倍(アームBがT0で232候補を評価するため)。
  実測: 20シャード×300ディールで約1.2時間・**約$5.7/セット**。
- 判定は `ai/tutor/verdict/mirror_verdict.py`(本セッションで新規作成)。
  **公式採点 = settle + entry クレジット**をデフォルトにし、FL価値ゼロ採点を
  併記する。旧 `pooled_verdict.py` はゼロ採点のみで、union の勝ち幅を
  +0.325 ではなく +0.125 と誤って記録していた。

## 4. 運用で踏んだもの

1. **マッチ艦隊のVMは公開後も自滅しない。** 公開済みシャード集合と生存VM集合が
   完全一致した時点で「全員が終わって空転中」と読む。台数では完走と
   プリエンプトが区別できない。
2. **プリエンプトは europe-west4 に集中**(rk1: 0,2,5,8 / rk1b: 0,2,5、
   両run で同じ番号 = 配置が番号決定だから同じゾーン)。補充は us-central1 へ。
3. **gcloud の出力に `\r` が付く。** `--format="value(name,zone)"` をそのまま
   読むとゾーン名が壊れ、削除が全件失敗する
   (`Invalid value for field 'zone': 'us-west1-a'`)。`tr -d '\r'` を挟む。
4. VM削除は**名前+ゾーンを列挙したファイルから1行ずつ**。grep の除外フィルタは
   以前に計算中の6台を誤殺した前科がある。

## 5. T0 について現時点で言えること

**「T0のモデルを強くする」方向は、調べた2経路とも根拠が消えた。**

| 経路 | 状態 |
|---|---|
| 配信側(ランカーを外す/差し替える) | **否定**。絞り込みは +1.14 の利得 |
| ラベル忠実度(regret 1.03 を下げる) | **土台が弱い**。教師の自己regret 1.57 で、物差し自体がノイズに埋もれている(実測) |

補足: 教師深度の測定(`joker_teacher_depth_20260823.md` 段階1)も試みたが、
60ロールアウトでは候補間レンジ中央値 7.76 に対し教師の1-2位差が 0.110 で、
**分解したい差がノイズの70分の1**。一致率20%は無作為(25%)と区別できず、
「失う値」は −1.02 と負に出た(= 深い側がくじ引きになっていた証拠)。
必要精度はルートあたり1万ロールアウト級で、費用が2桁合わない。
**per-root の argmax 比較という設計自体を捨てる必要がある。**

## 6. 次にやるなら

今回の結果は「絞り込みは良い」なので、**ランカーを弱くする方向ではなく強くする**
のが筋になる。ただし注意: ランカーの仕事が FL 志向の事前分布であるなら、
gen-3 ラベルで素直に再学習すると**その事前分布が消えて弱くなる**可能性がある
(まさに本件のアームBが起きたこと)。再学習するなら、
**対戦で測るまで出荷しない**こと。

費用の目安: 同型のミラー1本で $5.7/セット、2セットで約$11.4、1.5〜2時間。
