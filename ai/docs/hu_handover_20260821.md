## 1. 今夜いちばん重要な発見 — 物差しの問題

この引き継ぎ書で1つだけ覚えるならこれ。

> **「共通の物差しで測れ」の次に、「その物差しは誰の分布か」を問え。**

同じデータから、算術的にどちらも正しく、**結論が正反対の2つの読み**が出た。

### 読み A: プールtest (lap1-test + lap2-test)

lap1単独・lap2単独・連結を、**どのモデルも訓練にも選択にも使っていない**行で採点
(正典doc §18)。→ **連結が6街すべてで最良**。lap2単独は6街すべてで負け。

### 読み B: lap別test

同じモデルを、**それぞれのlapのtest分割で別々に**採点 (正典doc §19)。

| 街 | lap1-test での最良 | lap2-test での最良 |
|---|---|---|
| T1-BB | lap1 **0.139** (lap2 0.386) | lap2 **0.143** (lap1 0.360) |
| T2-BB | lap1 **0.150** (lap2 0.356) | lap2 **0.153** (lap1 0.286) |
| T1-BTN | lap1 **0.346** (lap2 0.714) | lap2 **0.358** (lap1 0.590) |

**各モデルは自分の分布で約2.5倍良く、相手の分布で約2.5倍悪い。**
連結はどちらの分布でも専門家に 0.04〜0.07 負ける妥協。

読み A のプールtestは**半分が gen-1 の分布**で、エンジンがもう訪れない局面に
半分の重みを置いていた。**現在の分布だけで見ると lap2単独が連結を4街で上回る。**

### だからどうするか

**regret では決められない。対戦だけが決める。** 本プロジェクトは
「忠実度の改善が勝敗に転写されない」断絶を既に3回踏んでいる
(正典doc、[[leaf-truncation-costs]]、[[m7-t1-relabel]])。3アームで測る。

### 副産物: ラップは効いている

オーナーの問い「データ量ならラップする必要は？」への答えは **量ではない**。
lap1のデータをいくら積んでも gen-2 が到達する局面の精度は上がらない。
上の対称性がその証拠で、**本プロジェクトでon-policyの効果を直接測ったのは初めて**。

**T3だけ連結が両分布で最良** — 盤面11+9枚で未知が少なく、分布が違っても打つ手が
変わらない。蒸留がT3で効いてT0で効かなかったのと同じ軸 (正典doc §13)。
**未知が多い街ほど分布が効く。**

## 2. 次にやること (順番どおり)

### 2.1 エンコード完了を確認 (自動、放置可)

```bash
python -m ai.tutor.fleet.backfill_street_fleet   # 既に走っている
```

**完了判定はラベル数ではなく npz (3本/シャード × 20)。**
lap 1 では「ラベル完了で監視を外し、エンコード45/60で永久待機」を踏んでいる。

### 2.2 `union_finish.sh` の出力を読む (自動)

`/d/ofc_data/hu/union_finish.log` に、8街ぶんの判定表が**2つの物差し両方で**出る。
その後 `models_verdict.tar.gz` (3アーム) が GCS の `hu-street/artifacts/` に上がる。

アーム構成: `gen2` = lap1単独 (= `models_t3ab/a` そのまま) / `lap2` = lap2単独 /
`union` = 連結。**rankers と own_lap4 は3アームとも同一** — 測るのは評価器の差だけ。

### 2.3 受け入れ試験 (必須、数分・数十セント)

```bash
bash ai/tutor/fleet/launch_verdict.sh accept gen2 gen2 40 86000001 1
```

**同一アーム同士のミラーは全ディールで厳密ゼロ**でなければならない。
ゼロでなければバンドルの組み立てミス。

**逆向きの罠**: T3街バグのときは「厳密ゼロ」が**設定を読んでいない印**だった
(正典doc §10)。異なるアームを指定して厳密ゼロなら、それは「差なし」ではなく
「モデルが読まれていない」。**両方向に効く試験である。**

### 2.4 ミラー2本 × 2シードセット (オーナー承認後)

```bash
bash ai/tutor/fleet/launch_verdict.sh v1  union gen2 12000 86000001 20
bash ai/tutor/fleet/launch_verdict.sh v1b union gen2 12000 87000001 20
bash ai/tutor/fleet/launch_verdict.sh v2  lap2  gen2 12000 86000001 20
bash ai/tutor/fleet/launch_verdict.sh v2b lap2  gen2 12000 87000001 20
```

`--hands` は**ディール数**。ミラーは1ディールを席交換で2回打つので 12,000 = 24,000ハンド。
**同じシードセットを両対戦で使う**こと — そうすれば2つの勝ち幅が同じ物差しに乗る。

見積もり: 1セット 20台×約1.7時間・約$8、4本で**約$33**。
**ただしこれは自己対戦の実測 (200サンプルで14コア機が16ハンド45.6秒) からの外挿で、
別アーム同士のミラーの実測ではない。** 1本目で置き換えること。

**判定基準**: セット内CIは信用しない。**最低2セット、プールで判定**。
m7/m7b ではCIが重ならず符号も逆で、どちらも単体なら「有意」に読めた (正典doc §2.1)。

## 4. 運用の罠 (すべて今夜または直近で実際に踏んだもの)

1. **`--dry-run` の quota は作成時の実容量ではない。** 全offsetで「20台入る」と
   答えるのに、実際は40台中11台しか作れなかった。**起動直後に必ず実測**し、
   足りなければ `--placement-offset 41 --skip-done` で us-central1 に直行させる。
2. **`--skip-done` は quota チェックの後に効く。** 生存分を引いた数ではなく、
   **要求シャード数がまるごと入らないと SystemExit**。これは警告ではなく死。
3. **判断はすべて「公開済みシャード番号」で行う。** 台数・ラベル数・生死は代用に
   ならない。完走したシャードも取られたシャードも「VM 0台」に見える。
4. **マッチ艦隊にリーパーは付いていない。** 付け忘れると完走VMが quota を占有して
   残りが起動できない (tr3で90分・$10)。`launch_verdict.sh` は同時に張る。
5. **補充の完了判定は最終成果物 (npz)。** ラベル完了で監視を外すと lap 1 と同じ
   「エンコード45/60で永久待機」を踏む。
6. **記録された故障は構成込みで読む。** [[gcp-zone-reachability]] は
   「europe-west4-a は GCS に届かない」と言うが、今夜の10台は外部IPを持ち
   `artifacts_ok` を公開していた。**削除しかけて実測で止めた。**
7. **定数は必ずファイルを読む。** 記憶の旧 fl_ev 表で採点して +1.66 と誤報告した
   ことがある (実際は +1.296)。`ai/config/fl_ev.json` が正。
8. **python の `write_text` は Windows で CRLF 化**し bash スクリプトを壊す。
   パッチ後は `sed -i 's/\r$//'` を必ず通す。
9. **`shell=True` は gcloud のパスの空白で壊れる。** argv リストで渡す。

## 5. オーナーとの仕事の仕方

- **日本語**。
- **データ駆動のみ**。ルールベースの手当ては明確に拒否されている
  (「あまりルールは使いたくないです」)。
- **報告は15分ごと** (この夜の指示。当初10分から変更)。
- **課金する操作は事前承認を取る。** 艦隊投入・大規模対戦は必ず伺う。
- **通知の数値を鵜呑みにして報告しない。** 節目の数字は実測で裏を取る
  — この夜、順不同で届いた通知の未来値をそのまま報告する誤りを1度犯した。
- オーナーは測定の穴を突いてくる。「悪化したらダメでしょ」「データ量ならlapする
  必要は？」はどちらも**こちらの結論の土台を崩す正しい指摘**だった。
  反論する前に測り直すこと。
