## 7. 診断 — 漏れの正体は半分が柵、半分が評価器 (9/3)

error 102件について、審判の最善手が配信のどこにいたか(エンコード時の順位キャッシュから):

| 指標 | 値 |
|---|---|
| 評価器の順位: 1位 / ≤3 / ≤8 / 中央値 | 19% / 41% / 67% / 5位 |
| ランカー柵(≤4)の内側 | 50/102 = 49% |
| 漏れの配分(マージン合計) | **柵で締め出し +201 (54%)** / **柵内で評価器が誤選択 +170 (46%)** |
| 評価器は既に1位と分かっていて柵だけが邪魔 | 19/102 |

含意: 柵を広げても評価器が拾わない(K=8ゲート+0.011の理由)。評価器を直しても半分しか届かず、
475ルートでは副作用が回復を相殺した(egate −0.025)。**T0-BBの順路(方策柵→方策改良→評価器矯正)
を踏むのが筋**: BTNには方策柵が無く、汎用ランカーが柵をしている。密ラベルは
`t0r1_labels/t0_btn_l{1,2}.jsonl` に存在(第1段の事前訓練が可能)。

並行: 副作用を削った再訓練(undecided_weight 0、ep4、3シード)をローカルで回し、46%側が
今の教材で取れるかを見る。ゲートは結果を見てから。

**副作用低減版 (9/3)**: undecided_weight 0・ep4・3シード → 保留一致 40.4/44.7/42.6%、回復 7/8/9 of 28、
破壊 7/6/8、agree移動 60/46/51。元レシピ(ep8: 一致48.9%、破壊4、agree移動50)と区別不能。
**副作用は475ルートで評価器全体を動かすこと自体に内在** → この経路のゲートは出さない。
判断: 評価器矯正は打ち切り、**Button方策柵**(BBの順路の第1段)へ。
