## 4. 学び(確定したもの)

1. ~~審判の値で測れる改善は、実戦に転写する保証がない~~ **撤回(9/4夜、§0)**: ゲートの FLゼロ採点を判定と読み違えていた。公式採点では研ぎラベルは +0.21/deal で勝ち、審判の予測(理論 +0.16)と整合。学びは「ゲートは公式行(1行目)を読む。記録には公式/FLゼロを明記して両方残す。出力は UTF-8 で」に置き換える
2. **蒸留継続(fast)は「良い手同士の順位」は保つが「危険な2枚上段の罰」に弱い** → 審判の採点には可、T0の指名には不可
3. **浅い検収は対照を置かないと解像不能**(96 rollout: fast ρ 0.513 vs 対照 0.510)。512 で初めて判定できた
4. **測定器は走らせる前に監査する**。4バッチの `3*se` は帰無で2.9%を確定させる(自由度3)。固定深度でも自由度が低ければ同じ罠
5. **失点地図は団子の順位を解像できない**(0.016-0.073 vs 分解能 ±0.03)。掘ることが測ること
6. **BTN の T0 は約22%が試写雑音で手が決まる**(柵内4候補が無差別)。配信のシードを与えれば監査は50/50再現
7. **配信の評価器は柵の外で信用できない**(場全体regret 2.83)。だから柵拡張単独は効かない
8. 艦隊の穴: 起動スクリプトごとにバンドル配置規約が違う(`models/` vs 名前一致)、src tarball は `ai/` 全体(30MB版)、run-idにアンダースコア不可、`gcloud storage cat "*.jsonl"` のglob読みは過小、対戦VMは自己削除できない(awkでペアを回して削除)、エージェントは待機で止まる癖(検証は自分で)
