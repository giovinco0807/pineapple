## なぜT2/T3のようには勝てなかったか (仮説、未分離)

1. **データ密度**: T0は行動空間~232手/ルート(5枚全配置)に対しルート23.1k —
   T3(~12手×45k roots)比で手あたりの実効データが1/16。T0-BB regret 0.641が示唆。
2. **鎖の減衰**: T1教師=V2sネット切断、T0教師=V1s(そのV1sはT1ラベル=V2s産)。
   厳密groundの恩恵が段ごとにネット誤差で薄まる。
3. **T0-BBの情報集合は5枚だけ**で既に飽和気味(8/24実証)。オーナーの当初案
   「T0は後攻だけ」の方向が正しかった可能性。
4. 配信はランカーtop-4+own連合でモデル差がさらに濾過される。

## 事故と教訓 (4件)

1. プリエンプト3件 — enc欠けでシャード特定→skip-done→余剰即削除の定型で全回復。
2. 劣化VM: btn_l2の1台が2.2hでシャード43% → kill+作り直しで約1時間節約。
   一方 T0エンコード55分は正常範囲だった(慌てて殺さない)。
3. **skip-done全滅罠**: 対象ジョブのVMが全滅した状態で--skip-doneすると全シャード
   再作成される(生存VM基準のため)。直後に完了済み担当VMを1行ずつ削除して
   欠員担当だけ残す。
4. **offset罠**: 空き割当は撤収したゾーン(計画の先頭側)にあるのに、大きな
   --placement-offsetは計画の尻尾しか見ないため「quota fits 3」と誤答する。
   補充・後発投入は offset 0 側から。
