# 対FL 世代2教師 — 設計 (2026-08-31)

オーナー提案(2026-08-30)「T0の教師ラベルを作る際、T1やT2も厳密ではないにしろ粒子を
増やしてラベルにできないか。そっちの方が効率が良い」の実装。監査(本番をそのまま再生)
から教師(内部ノードで最善を尽くした深い値)への移行であり、同じ計算からT1ラベルを
同時収穫する。

## 構造的な鍵

T0は5枚全置きで捨て札がない → **T1の3枚引きはT0の選択と独立**。
同一のT1引きセットを全T0候補が共有できる(CRN + レギュラー版の引き木共有)。

## 1ルートの手順

1. T0候補場: 出荷済み幅120ネット(models_ship_20260901/own_lap4/t0.bin)のtop-K
   (既定K=12; 20本に1本は全232のカナリア)。
2. T1引きを N1=16 本サンプル(シードはルートindexから、全T0候補で共有)。
3. 各 (T0候補, T1引き) 状態で **T1レース**: T1の合法手(2枚置き+1枚捨て)を
   ギャップ淘汰(1位との差、3σ+床)で絞り込む。各T1手の評価 =
   T2チューザ(own_lap4/t2)→T3/T4は現行の厳密own-worthで N2 本の将来を再生した平均。
   ラウンド粒子は控えめ(例 8→24→64)、勝者だけ追加測定。
4. T0候補の値 = mean over T1引き of (T1レース勝者の値)。
   = 「T1で最善を尽くしたときのT0の価値」— ブートストラップ1段分の除去。
5. 記録:
   - T0ラベル: 候補ごとの値+SE(SE同載はレギュラー版の教訓)
   - **T1ラベル(副産物)**: 各(状態, T1候補順位表+SE)。状態はT0上位候補由来のみ
     on-policy扱いで採用(rank≤4)、それ以外は low-confidence フラグ付き保存

## コスト規律

- Phase 1: プロトタイプをローカルで1ルート走らせ、実測でスケジュール(K, N1, レース粒子)を
  調整し **目標 ~3-5分/ルート** に収める。ハンド単価は~0.7ms(120化で試写なし)なので、
  支配項はレースの本数設計。実測が出るまで艦隊の話をしない。
- 共有できる固定費は共有する: T1引きセット、(T0候補,T1引き)ごとのT2以降の
  将来サンプル(CRN)、rowwiseメモ。
- シード帯: **910M**(T1引き) / **920M**(レース) / **930M**(追加測定)。900M以下は使用済み。

## 検収 (Phase 1)

1. 1ルートのT0値が、既存の審判(material_final)のsel_meansと方向一致すること
   (深い値なので水準は変わってよい。順位の大逆転が出たら精査)。
2. T1ラベルの形式: {state(board+draw), candidates:[{key, mean, se, n}], provenance}。
3. 実測レポート: 分/ルート、ハンド数内訳(T1レースが何割か)、K/N1感度の1点比較。

## その後 (Phase 2, 承認制)

- 頻度順1,000クラス(+接頭辞拡張)を艦隊で($数十の見込み) → 幅120チューザの再訓練
  (矯正でなくフル再訓練も比較) → 検収は同じ「新規クラス直接対決+CI」方式。
- T1ラベルが貯まったら own_lap4/t1(96次元ブートストラップ)の同型アップグレード
  (幅120化+この教師) — 対FL連鎖の2段目。

## Phase 1 実測と設計変更 (2026-08-31)

### レースの床ゲート修正 (実装済み)

淘汰規則は `3σ + 8点床` のままだが、**床が発火できる最小粒子数を「第1ラウンドの
累積粒子数」に変更**した(旧: ハードコード24)。理由は実測:

- 旧規則、schedule 6,16 では第1ラウンドが n=6 にしか達しないため床は一度も発火せず、
  48ノード中46ノードが候補4本を全て最後まで運んだ。淘汰機構は事実上飾りだった。
- 新規則では 48ノード中33ノードで淘汰が発火。ハンド数 3,426 → 2,836 (-17%)、
  時間 3.66 → 2.75 分/ルート (-25%)、T0順位はほぼ不変 (Spearman +0.943)。

CLI: `--teach-floor-min-n`(0 = スケジュール先頭を使う、既定)。

### コスト実測 — 仕様の 0.7ms/hand は成立しない

実測 **64 ms/hand**(ジョーカー無しルート 38.6ms、t0c-00007 68ms)。差の原因は
**110次元T2チューザの400完了サンプリング**で、0.7ms は「試写なしチューザ」を
前提にした数字だった。仕様の既定 (K=12, N1=16, 8/24/64) は約74,000ハンド ≈ 84分/ルート。

調整後の設定(目標内):

```
K=6  N1=8  t1_top=4  schedule=6,16  winner_extra=24  sigma=3.0  floor=8.0
```

### 幅120 T2チューザ — 教師には採用、配信には保留

同じ 96+cheap-draw-v2=120 構成が T2 盤面でもそのまま成立(実T2盤面402件で
Python/Rust 完全一致 0.000e+00)。**新しい幅は不要**。

| T2チューザ | dev regret | mae | corr | 教師 ms/hand |
|---|---|---|---|---|
| 96 (jointなし) | 0.60558 | 1.28924 | 0.95763 | — |
| **110 (出荷中, joint 400サンプル)** | **0.40417** | 0.92580 | 0.97762 | 58.1 |
| 120 (cheap draw, 試写なし) | 0.49873 | 1.06296 | 0.97132 | **6.3** |

- cheap-draw は 96→110 の差の **53%** を回復するが、T2 では joint ブロックに届かない。
  T0(空きスロット8)と違い T2(空き4)では joint が終端に近く情報量が高いためと考える。
- しかし**教師のT0順位は両者で完全一致 (Spearman +1.000, 平均差0.70点, argmax同一)**。
  T2チューザの精度低下はラベル対象の決定より下流にあり、全候補にほぼ等しく効くため。
- 結論: **教師では120を使う(9.2倍速、順位コストゼロ)。配信のt2.bin置換は別ゲートで、
  現時点の証拠は「保留」**(regret +23%)。
