# T2チューザ幅128 — jointの正体はmean1次元、コストの正体は反復順 (2026-08-31)

「幅120はjointとの差の53%しか回復しない(regret 0.499 vs 0.404)」
(fl_gen2_teacher_spec_20260831.md §幅120) の続き。ギャップの中身を
オラクル消去で特定し、jointを安くする2つの発見でregret帯を110の
近傍まで運んだ。全数値は dev 1,022ルート(24,843行動)、
`train_t4_first_evaluator --select-on regret --hidden 512,256,128`。

## 1. オラクル消去 — ギャップはjoint 8統計のどれか

encoded_110 のjoint列(dim 89-97)を encoded_120 のベクトルに接ぎ木して
再訓練するだけ。新しいエンコード不要、1変種3分。

| 変種 | 幅 | dev regret |
|---|---|---|
| 110 (基準, s20260814) | 110 | 0.40417 |
| 120 | 120 | 0.49873 |
| 120 + joint全8 | 128 | **0.40361** |
| 120 + mean(dim1)のみ | 121 | 0.41544 |
| 120 + foulのみ | 121 | 0.48074 |
| 120 + mean + foul | 122 | 0.42035 |
| 120 + 尾部2(P≥6,P≥15) | 122 | 0.41919 |

**mean(完了平均EV=best-selfのE)1次元がギャップの87%を運ぶ。**
foul率はほぼ無寄与 — cheap24とrowwiseが既に言えている。
diag(120が110に≥0.5負ける104ルート)でも、joint差分の符号一貫性は
mean(76/27)が突出。誤りの型は「ペア/トリップスをどの段に割るか」の
交差段配分で、これはrowwise(段別周辺分布)では原理的に見えない
将来ルーティングの期待値。

## 2. サンプル数はダイヤルにならない…そのままでは

mean1次元ならKを削れるかを実測(幅121で再エンコード):

| K | dev regret |
|---|---|
| 64 | 0.45384 |
| 128 | 0.44436 |
| 400 | 0.41544 |

K依存が強く、K=64/128は失格。そこでコストの内訳を疑った。

## 3. コストの発見2つ (実測40盤面, T2=空き4)

1. **厳密列挙は1.7µs/サブセット**(123,410全列挙=~200ms/盤面)なのに
   **sampled 400は~13µs/サンプル**。差の一部はSHA256シャッフル
   (レガシーサンプラーはスワップ1回=SHA256 1回、42回/サンプル)、
   残りは**ランダム順アクセスでrow memoの局所性が死ぬ**こと。
2. 対策: (a) `CompletionSampler::SplitMix` — seedを1回だけSHA256し
   splitmix64で部分Fisher-Yates。(b) K本を先に引いて**辞書順ソートして
   評価** — 統計は同一集合の平均なので不変、決定性も保持、memoが温まる。
   → **3.3µs/サンプル、K=400で2.9ms/盤面**(sha256比~3倍速)。

レガシー経路はバイト不変(golden bitsテスト通過)。sampler は
`--joint-outlook` のリクエスト新フィールド、serve側は幅でディスパッチ。
**旧バイナリはsamplerフィールドを黙って無視してsha256で走る** —
幅128系の艦隊はこの変更後のbinstampが必須。

## 4. 幅128 (splitmix K=400) — 本命の実測

幅128 = actor48 | rowwise41 | context7 | cheap_v2 24 | joint8(splitmix)。
jointは**最後**に積む(104/110と違う)。playout.rs
`FL14_CHEAP_V2_JOINT_SIZE` ブランチ実装済み、シード規約
`joint/{node_seed}` とroot内メモ共有は110と同一。

- **パリティ**: 訓練経路(Python組立+--joint-outlook) vs 配信経路
  (--encode-features→encode_for)、402実T2盤面×128次元で **0.000e+00**。
- **コスト**: 配信経路2.3ms/盤面(rowwiseメモ非共有の上限)。
  110は同条件~8-10ms。
- **regret 3シード帯**: 0.4126 / 0.4142 / 0.4198 (平均0.4155)
  vs 110帯 0.4042 / 0.4062 / 0.4133 (平均0.4079)。**Δ+0.008残る**。

## 5. 反証済みの脇道

- **厳密列挙(samples=0)**: 既にコード内に存在するが200ms/盤面で配信失格。
  教師コーパスなら焼けるが、配信と分布が割れるので却下。
- **allocation6の追加(幅134)**: 0.4237/0.4180/0.4178 — **悪化**。
  cheap24の生ランク和が同じ情報を既に運んでいる。
- **K=64/128**: §2の通り。mean1次元でも雑音が順位に乗る。

## 6. K=1024 と、雑音devの崩壊 (8/31深夜)

雑音dev(t3_draws=12ラベル)上のK曲線:

| 構成 | シード3本 | 平均 |
|---|---|---|
| 110 (基準) | 0.4042 / 0.4062 / 0.4133 | 0.4079 |
| 128 K=400 | 0.4126 / 0.4142 / 0.4198 | 0.4155 |
| 128 K=1024 | 0.3947 / 0.3986 / 0.3942 | **0.3958** — 全シードで110超え(に見えた) |

しかしpaired bootstrap(1,022ルート)では K=1024−110 = −0.014
CI[−0.053,+0.023]、シード物差し(110同士)が+0.010 CI[−0.017,+0.038] —
**雑音devはこの桁の差を裁く分解能を持たない**。

### 研ぎ済み判定 — 争点ルートの高粒子再ラベル

Δregret(root) = sharp(v(110のpick)) − sharp(v(挑戦者のpick))。
「真の最善」項は差分で相殺されるので、**不一致ルートの2候補の再価格だけで
モデル差は厳密に出る**。不一致ルートのみをt3_draws=192×2独立パス
(stream 940M/950M、fl_ev_prevテーブル=原本ラベルと同一意味論、
1.74s/ルート)で再価格:

| 比較 | 旧ラベル | **研ぎ済み** | ラベル雑音SE |
|---|---|---|---|
| 128_k400 − 110 (333争点) | +0.013 未決着 | **+0.049 [+0.024,+0.074] 劣後確定** | 0.005 |
| 128_k1024 − 110 (305争点) | −0.014 「勝ち」 | **+0.019 [−0.002,+0.041] 勝ちは幻** | 0.004 |

符号反転は95/333、84/305。**雑音devは±0.02〜0.04の判定を系統的に
誤らせる** — 幅134(alloc追加)の棄却判定(§5)も同じ雑音devによるもので、
現時点では信用できない。

なぜ系統誤差になるか(仮説): チェックポイント選択(--select-on regret)が
雑音devのregretを直接最適化するため、dev雑音への適応が起き、
特徴構成によって適応幅が違う。研いだラベルはこの適応分を剥がす。

## 6.5 最終判定 (9/1未明、研ぎ済みdev + 際どいルート厳密化)

測定器: (a) 全1,022 devルート×全候補をt3_draws=96×2独立パスで再価格
(D:/ofc_data/lap4_t2_own/sharpdev/、~3時間)、(b) それでも未決着の
際どい284ルート(3σ判定)だけ **T3引き全列挙(C(41,3)=10,660)** で厳密化。
厳密化はpilot下見32本/keep2でT3配置を絞る(5ルート検証: ルート内
キー間差≤0.016、全配置厳密の4倍速16.6s/ルート、59.6分で完走)。
teach-t2に `--t3-draws 0`=全列挙モードを実装(t2_labels.rs)。

研ぎ済みregret水準(2パス、雑音SE~0.0055):
110=0.121-0.128 / 128k1024=0.135-0.145 / 128k400=0.160-0.169 /
134=0.177 / 120=0.253。**旧dev(12draws)の0.40の6割はラベル雑音の濡れ衣**。

paired最終判定(vs 110_s14、争点は厳密値、差分恒等式でバイアス相殺):

| 挑戦者 | Δregret | 95% CI | 判定 |
|---|---|---|---|
| 110_s15/s16 (物差し) | −0.001 / +0.005 | ±0.018 | シード床 |
| 128_k1024 ×3 | +0.032 / +0.020 / +0.022 | s14はCI正 | **勝てず** (1本は劣後確定) |
| 128_k400 | +0.050 | [+0.023, +0.078] | 劣後確定 |

雑音devの「k1024全シード勝ち(0.396 vs 0.408)」は、ラベルを研ぐほど
逆向きに単調に崩れた(−0.014 → +0.019 → +0.022)。**チェックポイント選択が
雑音devに適応した分が、そのまま偽の勝ち幅だった**と読む。
