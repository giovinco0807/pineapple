# HU梯子の再生産設計 — 蒸留と再ラベルの正典 (2026-08-18)

ジョーカートラックHUフェーズの設計文書。2026-08-16〜18の実測に基づき、
「どう強くするか」の方法そのものを定義する。数値はすべて実測。

## 0. 一行の要約

**地面は厳密解、ラベルは消耗品、モデルは中間生成物。**
強さはラベルの4入力（抽選の深さ・root分布・相手モデル・fl_ev）を更新する
周回から来る。蒸留とフリートは周回の値段を1〜2桁下げる下回りであり、
それ自体は強さを1点も足さない。

## 1. 梯子の構造

```
厳密V4 (v4_first.rs, 0.8ms/状態, 誤差<1e-9)   ← 恒久的な地面。絶対に近似しない
  ↑ 直読み
T3教師  BTN: -V4スワップ直読み（決定的・厳密）
        BB : 相手半街16抽選×チューザ → V4直読み（Rust t3_first_hu, 447ms/root）
  ↓ root最良値
V3s 境界ネット（207次元ペア → 先手価値）
  ↑ 読み
T2教師  BTN: V3s 1読み（決定的）
        BB : 相手半街16抽選 → V3s読み（Python hu_street_teacher, ~5s/root@8vCPU）
  ↓ … 同型で V2s → T1 → V1s → T0
```

- 符号化は207次元ペア（自陣110=actor48+rowwise41+joint8+context7+alloc6、
  相手97）。joint 8次元×両側だけが400本ロールアウトで、コストの99.99%。
- 席の非対称: BTNの後状態は次街境界にそのまま着地（ラベル決定的）。
  BBは相手半街の期待値が要る（ここにラベル雑音が入る）。

## 2. ラベルの規格 — 何が「最高のラベル」か

| 規格 | 値 | 根拠（実測） |
|---|---|---|
| BB席の相手半街 | **16抽選**（トレース1標本は禁止） | 1標本→16抽選でラベルが平均**7.8点**移動。V3s MAE 11.53→**8.27**（床8.05）。T3-BB production regret 0.336→0.302 |
| 相手チューザ | 現行はgen-3 ranker96（**要更新→現行チェーン**） | 自己対戦整合。未実施 |
| joint抽選 | 400本・**決定単位の共有シード** | 候補ごとに引き直すと雑音が順位に直撃（CRN原則） |
| 深さの限界 | √N逓減 | d8対d16のtop-1一致61%は参照自身の雑音で膨らむ（選択バイアス）。16で主要部は取得済み |

### 再ラベルのy-swap（ロールアウト再符号化の全面回避）

再ラベルは値を変えるが盤面を変えない。よって既存の特徴行列（207/432/623次元）
は全部再利用し、yだけ差し替える（`ai/tutor/swap_hu_labels.py`）。
書き込み前に3つの証明を要求: root列一致・旧値一致・新ラベル完全被覆。
**照合に失敗したら書かない**（ずれたラベルは「正常に見えて全部間違い」を作る）。

## 3. 蒸留の規格 — 抽選は入力でなく教師

### 設計（`ai/tutor/train_hu_aux.py`）

- 入力: **ハイブリッド623次元** = カードone-hot 432（8ブロック×54、
  `encode_hu_cards.py`、ソルバー不要）+ 安い特徴191（207からjoint16を除く）
- 補助ヘッド: joint16統計を**訓練時の予測目標**にする（λ=2）。servingでは捨てる
- 効果の機序: (a) ネットは400本ラベルの雑音を均し無限本jointに収束
  (b) マルチタスク正則化がカード入力の丸暗記を防ぐ

### 実証済みの適用範囲

| 場所 | production | 蒸留 | 判定 |
|---|---|---|---|
| T3-BTN 評価器 | 0.292 | **0.238** | **採用**（2シード再現） |
| T3-BB 評価器（d16ラベル） | 0.302 | **0.268** | **採用** |
| T3-BB（tracedラベル） | 0.336 | 0.705 | 雑音ラベルでは崩壊（=雑音仮説の証明） |
| T2-BTN 評価器 | 0.315 | 0.471 | 不採用（4/4スロットの深さ壁） |
| V3s 境界（4/4スロット） | 8.27 | 9.01 | 不採用・ベンチ（スート増強×24が次の梃子） |

### 失敗から得た構成要素の必然性

- カードone-hot単体: regret 6.59（fit 2.1/dev 9.8の丸暗記）→ 足場が必須
- 安い特徴単体: 0.550 → 情報が欠落
- joint16を安い191次元から予測: 天井0.414 ≒ joint抜き再学習0.4136
  （**入力に無い情報は予測でも増えない** — 一致は偶然でない）
- jointの寄与カーブ: T0 +0.087 / T1 +0.131 / **T2 +0.331 / T3 +0.259**
  （寄与は浅い街で大きい。蒸留可否の判別力もそこにある）

### 規律（劣化防止）

1. 地面（厳密V4）は永遠に蒸留しない
2. 蒸留ネットを**教師に昇格させる前に**、MAEでなくラベルの順位一致で
   production参照と照合する
3. 世代ごとに対戦で採点する（内部指標は全て教師への忠実度であり、
   全指標良好のまま実戦で負けた前科がある）

## 5. 計測の規律

- **regretの罠**: 雑音ラベルに対するregretは必ず上振れする（root内最良が雑音で
  嵩上げ）。BTNとBBの数字の直接比較は不可
- **較正の検査**は slope(truth~pred)。slope(pred~truth)は条件付き期待値なら常に<1
- 境界ネットのMAEには**削減不能床**（pre-draw netの抽選分散、実測8.05）がある。
  床近傍のMAE差は品質差ではない
- 唯一自分を騙せない指標は**実収支の対戦**（ハーネス: hu_match.rs、FL・stay・
  セッション200点/40点差/席交代込み）

## 9. 審判の結果と欠陥の発見（2026-08-18 昼 追記）

**修理は対戦を悪化させた**: m1(旧)−0.544 → m2(T1-T3修理)−0.779 → m3(+T0)−4.108。
FL進入 31.3%→29.3%→19.6%。同一シード対比較で m3−m1 = −3.57（決定的）。

**真因は価値理論でなく分布欠陥**: 境界ネットV_kはトレース由来の
（実盤面,実盤面）ペアだけで学習しているのに、展開教師は
（任意候補,任意サンプル配置）ペアで読む — 完全な外挿。ネットは出鱈目な
相手盤面を「弱い」と誤読しヒーロー値を**一様に約+8点膨張**させる
（同一root・同一ネットでtraced −6.24 vs 展開 +1.97。min/mean/抽選数の
影響は±0.3で無関係）。BTN側は−V読みで−8となり、段を上るたび境界目標に
焼き込まれ複利化（V2s目標+7.7、V1s+10.5、T0-BBラベル+12.3）。

**副次の実バグ**: 教師の抽選シードがPython `hash()`（プロセス塩付き）で
ラベルが再現不能だった → hashlib化済み。

**帰結**:
- v2/d16系の街ラベル・境界ネット・モデルは全て汚染資産として隔離
  （T3のRust教師成果物のみ厳密読みなので無事）
- 対gen-3チャンピオンは旧チェーン（m1構成）のまま
- 旧チェーンが機能していた理由: tracedペアは片側が実盤面で、
  ネットの学習分布に半分乗っていた

**恒久修理の設計（世代2の前提）**: 境界ネットは「読まれる分布」で学習する。
V3sは、T2教師の展開が実際に生成するペア分布から状態を採取し、
Rust d16チューザ教師（厳密V4基盤、~340ms/状態）でラベルして
トレースペアと混合学習 → 以後の段も同型。読む分布と学習分布の一致を
各rungの合格条件に加える。

## 10. 真の根本原因（2026-08-18 夕 確定 — §9を上書きする）

m1→m3崩壊の根本原因は境界ネットの分布外読み（§9の診断）**ではなく**、
`hu_street_teacher.py`の集計分岐1行だった:

```python
direct = args.seat == "btn" or "opp_after" in request   # ←バグ
```

trace由来のリクエストは全てopp_afterを持つため、`--no-traced-opponent`でも
集計はtraced直読み扱いになり、**展開16抽選×24配置を計算した後、先頭の
1ペア（最初の抽選の最初の任意配置）だけを読んでいた**。ペア構築側の条件に
`args.traced`を足した際、集計側を直し忘れた（フラグ追加時の自il傷）。

**帰結の再解釈:**
- 「16抽選ラベル」として作られた全BB展開ラベル（T2/T1のv2）は実際には
  「ランダム1配置ラベル」。min/mean/抽選数が±0.3で無差だった理由=どれも
  実行されていない
- +8の一様膨張 = 相手が実配置(真値−5.8)からランダム配置(真値+1.6〜2.9)に
  化けた**本物の価値差**。ネットは両分布とも正確（バイアス±0.6）で無実
- §9のOOD仮説は撤回。ただし副産物2つは本物:
  (a) **敵対的裾のネット誤差+5.1**（真min配置−10.6を−7.9と読む）—
      将来min集計を使うなら要対策
  (b) OOD混合学習・採取器・厳密プローブの機構一式

**検証**: 修正後、教師=手組み再現がバイト同一抽選で一致（root0: −24.465
完全一致）。修正コミット時のガード: `direct`はペア構築分岐と同一条件を
共有すること。

**正しい修理（未実行）**: 集計=チューザ（相手配置は相手自身のown-hand
rankerのargmax、Rust T3教師と同型）×16抽選。minは(a)の裾誤差を踏むため
非推奨。gen-3の実挙動とも一致する。tracedラベル(m1)はこの正しい量の
1標本だったと再解釈される — m1が最強だった理由。

## 11. 修理の完成 — chooser16と新チャンピオン（2026-08-18 夜）

検証: 同一100rootでchooser16平均−6.13 vs traced−6.24（同じ量の低雑音版
であることを確認、相関0.82）。min型は敵対的裾のネット誤差+5.1を踏むため
不採用。教師リファクタは回帰差0.000000で施行。

**カスケード**（chooser16でT2-BB→V2s_c→T1両席→V1s_c→T0→学習→m5）:
依存グラフ並列化（T0はV1sのみに依存、T1-BTNの尻を待たない）で約4.5時間。
V2s_c16 MAE 5.58（traced時代7.25）、t1_bb_c16 regret 0.137。
