# FL経路 監査 (2026-07-30) — 未完了、次セッションへ引き継ぎ

## 結論(確定)

`fl_solver` は、正典のジョーカー制約を通さない配置を出力する経路を持つ。
報告される `is_bust` / `total_royalty` が正典評価器と食い違う。
**バグは `fl_solver` 内に限局しており、`ofc_core` は正常。**

## 最小再現ケース

```
top ['Kd','2d','Kc']   mid ['Qs','X2','7s','9s','4s']   bot ['Jh','9h','3h','6h','2h']

fl_solver (version 2): is_bust=false, total_royalty=20
Python 正典          : busted=true,  royalty=0
```

ファウルの機序は**上段vs中段**である。中段はジョーカーでスペードフラッシュに
できるが、それは下段のJハイ・ハートフラッシュを上回るため、正典は中段の
ジョーカーを `Qh` へ落として**クイーンのペア**にする。すると上段のKKが中段QQを
上回り、上段にジョーカーが無いため救済できずファウルする。
`fl_solver` は中段をフラッシュのまま数えて royalty 20 を主張している。

再現コマンド(13枚をそのまま渡すので配置は一意):

```
python -m ai.tutor.audit_fl_solver --hands 400 --cards 14 --version 2 \
    --out ai/reports/fl_path_audit_20260730/v2_14.json
```

平均royaltyは申告 14.36 / 正典 14.27 (**0.6%**)。この差はハンド分散に埋もれるため、
EVやファウル率を見る通常のベンチマークでは**原理的に検出できない**。
「FLベンチマークでバグは出なかった」という既存の観測と矛盾しない。

速度: v2 = 7.2ms/手、v1 = 107ms/手 (v2が約13倍速)。

| 対象 | 状態 |

(`canonical_rows` の呼び出しは 483 / 727 / 814 / 1047 / 1109 / 1145 行)。
