# T2-vs-FL v1: 相関0.99でもゲート不合格、原因は省略したjointブロック (2026-08-04)

## 結果

| 指標 | T2 v1 | 参考: T3-vs-FL v2 |
|---|---|---|
| 教師 | 12k root / 200,511行 / 11.4h | 30k root / 353k行 |
| test相関 | **0.9898** | 0.9768 |
| test MAE | 0.687 | 0.443 |
| charged regret | 0.335 | 0.106 |
| 審判フロア | **0.070** | 0.099 |
| **gap over floor** | **0.265** | 0.0036 |
| 判定 | **FAIL** | PASS |

joker層別 charged regret: 0枚 0.284 / 1枚 0.303 / **2枚 1.327**

## 診断

**ラベルは良い**(フロア0.070はT3の0.099より低い＝プレイアウトラベルは
むしろ静か)。**モデルが悪い**。しかも相関0.9898が全く役に立っていない——
T3 v1と同じ「相関は健全、行動選択で不合格」の再演。

原因は設計時に明示的に賭けた点そのもの:
`generate_t2_vs_fl_teacher.py` のdocstringに「四つの空きスロットのjointブロックは
意図的に省略。regretゲートが不足かどうかを決める」と書いた。**ゲートの答えは
「不足している」**。

裏付けはjoker2層の 1.327(他層の4.4倍)。ジョーカーは行をまたいだ柔軟性そのもので、
「どの完成を同時に満たせるか」を表すのがまさにjointブロック。行別ヒストグラム(rowwise)は
各行を独立に見るので、同時達成可能性を系統的に過大評価する——T4診断で確立済みの型。

## 決定

1. **T1/T0のラベル生成は、このT2モデルを着手選択器として続行する。**
   根拠は実測: 60次元v1モデル(自身のゲートはregret 0.279で不合格)を
   プレイアウト着手器に使っても、ラベルへの影響はドローノイズ床の内側だった
   (argmax regret 0.026 vs 床0.078、`t2_policy_label_experiment.py`)。
   着手器の要求水準は評価器のそれより大幅に低い。
2. **T2評価器自体は修正が必要**(最終チェーンでT2の判断を担うため)。
   次の一手: **サンプリング版jointブロック** — プールから4枚完成をK通り抽出し、
   各々を貪欲評価して要約(foul率・平均EV・生存条件付きroyalty/FL・分散)。
   厳密列挙 C(40,4)=91,390 は高価すぎるが、TerminalMemo込みならK=200程度で安価。
   regular側は同じ問題を「4→6→8スロットのfree outlook一般化」で厳密に解いており、
   本気で厳密化するならそちらの移植が正道(統合フェーズ2以降)。

## 教訓(再確認)

相関・MAEは受け入れ基準にならない。**gap-over-floorだけが行動選択の質を測る。**
T3 v1(corr 0.931 → regret 0.279)、T2 v1(corr 0.990 → gap 0.265)と2度続けて
同じ形で現れた。
