## 1. まず「自分が作っているもの」の正体を知る

学習の前に、地図を持ちます。あなたのリポジトリは、外から見ると次のような構造です。

### 1.1 これは「深層学習プロジェクト」ではない

一般的なAI開発（画像分類、LLMのファインチューニングなど）は
「大量のデータ → ニューラルネット → 予測」という単純な形をしています。

**ofc-pineapple はそうではありません。** 中心にあるのは意思決定理論とゲーム理論で、
ニューラルネットは「厳密に計算した答えを圧縮して速く引くための道具」として
使われています。順番が逆なのです。

```
（一般的なML）      データ  →  NN  →  予測
（このプロジェクト） ゲームのルール → 厳密計算 → 教師データ → NN（圧縮） → 実戦での高速推論
                                    ↑ ここが本体
```

だから、あなたが学ぶべき順番も一般的な「ML入門」とは違います。
**確率と期待値 → 探索と厳密計算 → そのあとでニューラルネット**、が正しい順です。

### 1.2 ゲームそのものの構造

| 項目 | 実測値 | 出典 |
|---|---|---|
| カード枚数 | 54枚（52 + ジョーカー `X1`/`X2`） | `ai/engine/encoding.py` の `ALL_CARDS` |
| 盤面 | top 3枚 / middle 5枚 / bottom 5枚 | `Board` dataclass |
| ターン | T0（5枚配置）→ T1/T2/T3（3枚配られ1捨2配） | `ofc_computation_roadmap.md` |
| 合法手の数 | T0=232, T1=12, T2=9, T3=3 | 同上 |
| 状態ベクトル | **522次元** = 54×9 + 6 + 30 | `encoding.py` の `STATE_DIM` |
| 情報の非対称性 | 相手の盤面は見える／**捨て札は見えない** | `Observation.unseen_cards` |
| 勝敗単位 | 1ハンドではなく**セッション**（200点持ち・合計400点保存・40点差で終了） | `rl_environment_spec.md` |

### 1.3 いま採用されている設計思想（2026-07-31 時点）

`ai/docs/value_chain_milestones_20260731.md` は、このプロジェクトの
**現時点での最重要判断**を記録しています。要約するとこうです。

> 探索・方策ネット・MCTS を使わず、各ターンの価値関数を厳密解から下へ
> アンカーして積み上げ、全ターンを「合法手全列挙 → 評価器 → argmax」で打つ。

そして「使わないもの」が根拠つきで明記されています。

| 捨てたもの | 根拠（doc に記載の実測） |
|---|---|
| MCTS / PUCT | 評価が誤っていれば探索は最適に誤る（20,000シミュレーション実験） |
| 方策ネット / BC | Top-1 天井 30〜59%。値の argmax が方策 |
| 自己対戦の勝敗からの ValueNet 学習 | ノイズ天井（相関 0.79）の再現になる |
| 全面 MCCFR | 隠れ情報が捨て札≤3枚のゲームに対して不釣合 |

**この4行を「なぜそう言えるのか」自分で説明できるようになることが、
このロードマップ全体の最終目標です。** ここが分かれば、LLMが出す提案の
9割は自分で採否を判断できるようになります。

（注意：`ai/mcts/`, `ai/cfr/`, `ai/models/networks.py` などのコードは残っていますが、
最新の設計判断では主役から外れています。「なぜ作って、なぜ外したか」の歴史そのものが
最良の教材なので、フェーズ8・9でこれらを読みます。）

## 2. 学習の設計思想（なぜこの順番なのか）

### 2.1 理解には3段階ある

1. **動かせる** — コードを実行して結果が出る
2. **説明できる** — 何がどう動いているか他人に言える
3. **壊れ方を予測できる** — 「ここをこう変えたらこう悪くなるはず」と事前に言える

LLM に任せていると 1 で止まります。**提案ができるようになるには 3 が必要です。**
各フェーズの卒業判定は、意図的にすべて「3」を問う形式にしてあります。

### 2.2 下から積む

あなたのプロジェクト自身が「T4（終盤）から T0（序盤）へ下から積む」設計です。
理由は**誤差が上に伝播するから**。学習もまったく同じで、確率と期待値が
曖昧なままニューラルネットに進むと、そこから先の理解がすべて歪みます。

急いで上に行かないこと。これは根性論ではなく、フェーズ4で数式として理解できます。

### Phase 0 — 土台：Python と確率

**到達目標**
自分のリポジトリの Python を、行単位で「何が起きているか」説明できる。
確率と期待値を、手計算とシミュレーションの両方で出せる。

**中核概念**

- 確率: 標本空間、事象、独立、条件付き確率、ベイズの定理
- 期待値: `E[X] = Σ p(x)·x`、線形性 `E[aX+bY] = aE[X]+bE[Y]`

**自分のコードのどこを読むか**
- `ai/engine/encoding.py` の冒頭〜120行目付近

**演習**

3. サイコロ1個の期待値を手計算 → Python で100万回振って一致を確認。
4. 「52枚から5枚引いてフラッシュになる確率」を手計算 → シミュレーションで確認。

**卒業判定**
- 522 という数字の内訳（54×9 + 6 + 30）を紙に書いて説明できる
- なぜカードを one-hot（0/1のベクトル）で表すのか、整数のままではダメな理由を説明できる
- 9つの「ロケーション」（自分top/mid/bot、相手top/mid/bot、手札、自分の捨て札、未確認）が

### Phase 1 — ゲームを数学の言葉に翻訳する

**到達目標**
OFC Pineapple を「状態・行動・遷移・報酬」の4つ組で書き下せる。
合法手の数を自分で数え直せる。

**中核概念**
- 状態 (state) / 行動 (action) / 遷移 (transition) / 報酬 (reward)
- 組合せ論: 順列 `nPr`、組合せ `nCr`、重複の除去
- 合法手マスク (legal action mask) — なぜ必要か
- 意味的に同じ行動 (semantic aliasing) — なぜ重複が生まれるか

**自分のコードのどこを読むか**
- `ai/engine/action_space.py`
  - `get_initial_actions` — T0（5枚配置）。`itertools.permutations` で全列挙
  - `get_turn_actions` — T1〜T3（1捨2配）
  - `get_semantic_action_index` — `discard_idx * 9 + pos0_idx * 3 + pos1_idx`
  - `Action.__eq__` / `_canonical_placements` — **重複除去のロジック。ここが核心**
- `ai/engine/scoring.py`, `ai/engine/game_engine.py` — 報酬（スコア）の定義

**演習**
1. `get_semantic_action_index` の式から、行動インデックスの上限が 27 になることを示す（3×3×3）。
2. T3 の合法手が 3 通りしかない理由を、盤面の空きスロットから自力で導く。
3. T0 が 232 通りである理由を数え上げで再現する（`itertools` で全列挙 → 重複除去 → 数える）。
   **ぴったり合わなくてよい。合わない理由を突き止めるのが本当の演習です。**
4. 「意味的に同じだがインデックスが違う行動」の具体例を1つ作る。

**卒業判定**
- 「27スロットの行動空間なのに、実際の合法手は T1=12, T2=9, T3=3」というギャップを説明できる
- 合法手マスクを外したら何が起きるか、予測できる（→ Phase 6 で実験する）
- スコアが「ロウ勝負 + ロイヤリティ + ファンタジーランド」の3要素からなることを説明できる

### Phase 2 — モンテカルロと分散（このプロジェクト最重要のひとつ）

**到達目標**
「サンプル数を増やすと何が良くなり、**何は絶対に良くならないか**」を
数式と自分の実験の両方で説明できる。

**中核概念**
- 大数の法則 / 中心極限定理
- 標準誤差 `SE = σ / √n` — **サンプル100倍で誤差1/10**
- 信頼区間
- **バイアスと分散の区別** ← このフェーズの主題
- 分散削減: 共通乱数 (common random numbers)、対照変量、層化サンプリング

**自分のコードのどこを読むか**
- `bench_pimc_1_sample.py`, `bench_pimc_500_samples.py` — サンプル数の違いを測るベンチ
- `ai/mcts/rollout_evaluator.py`（89KB。全部読まなくてよい。ロールアウトの構造だけ掴む）
- `analyze_dist.py`（リポジトリ直下）, `ai/analyze_p99.py`

**演習**
1. 同じ局面を n = 10, 100, 1000, 10000 サンプルで MC 評価し、
   誤差（標準偏差）を n に対してプロットする。**1/√n の直線が見えるか確認する。**
2. 「誤差を半分にするのに必要なサンプル数」を式から出し、実測と比べる。
3. **わざとバイアスのある評価器を作る**（例：常に0.3点だけ高く見積もる）。
   これを使って n を 100倍にする。誤差は減るか？ → **減らない。** これを自分の目で見る。
4. 3の結果を、`E[推定値] - 真値` と `Var[推定値]` に分解して説明する。

**卒業判定**
- `value_chain_milestones_20260731.md` の
  「**評価の誤りは探索量で救えない**（20,000シミュレーション実験）」を、
  演習3の自分の実験結果と数式で説明できる
- 「サンプルを増やす」提案と「評価器を直す」提案のどちらが必要かを、
  誤差の内訳を見て判断できる

> このフェーズを終えた時点で、あなたはLLMの提案の一定割合を却下できるようになります。
> 「精度が足りないのでサンプル数を増やしましょう」という提案が正しいのは、
> 誤差が分散由来のときだけです。

### Phase 3 — 不完全情報：PIMC は何を取りこぼすか

**到達目標**
PIMC（完全情報モンテカルロ）が何を近似していて、何を構造的に取りこぼすかを説明できる。

**中核概念**
- 情報集合 (information set) — 「自分から見て区別がつかない状態の集まり」
- 信念 (belief) / レンジ (range)
- **strategy fusion** — 各サンプル内で「相手の手札を知っている前提」で最適化してしまう誤り
- **non-locality** — 相手の過去の行動が現在の信念を変えるのに、それを無視する誤り
- 捨て札の尤度による再重み付け (discard likelihood reweighting)

**自分のコードのどこを読むか**
- `ai/prob_engine_wrapper.py`
- `ai/docs/hu_all_turns_contract.md` — 情報境界の契約
- `ai/docs/hu_gen2_onpolicy_20260819.md`, `ai/docs/hu_handover_20260821.md`
- `ai/engine/encoding.py` の `unseen_cards`（見えないものの定義そのもの）

**演習**
1. 「相手の捨て札が見える版」と「見えない版」で同じ局面を評価し、差を測る。
2. 自分の盤面・相手の盤面・自分の捨て札を全部並べ、
   **相手の捨て札 (最大3枚) だけが未知**であることを図に描く。
3. strategy fusion が起きる最小の具体例を、OFC の小さい局面で作る。

**卒業判定**
- `value_chain_milestones` の「隠れ情報が捨て札≤3枚のゲームに対して
  全面MCCFRは不釣合」という判断を、情報集合の大きさの観点から評価できる
- 「捨て札尤度の再重み付けを最終改修候補として保留」という判断の意味を説明できる

### Phase 4 — 後ろ向き帰納と価値チェーン（設計思想の心臓部）

**到達目標**
なぜ T4 から T0 へ「下から」積むのか、そして
「値ブートストラップ」ではなく「チェーン・プレイアウトの終端スコア平均」を
ラベルに使うのかを、**誤差の伝播として**説明できる。

**中核概念**
- 動的計画法 (DP) / 後ろ向き帰納 (backward induction)
- ベルマン方程式 `V(s) = max_a E[ r + V(s') ]`
- 厳密解 (exact solve) vs 近似評価器
- **誤差の複利** — 各段で評価器を葉に使うと誤差がどう積み上がるか
- ブートストラップ (値を値で学ぶ) vs プレイアウト・ラベリング (終端まで打って平均)

**自分のコードのどこを読むか**
- `ai/backward_induction.py`
- `ai/docs/value_chain_milestones_20260731.md` ← **このフェーズの主教材**
- `ai/docs/bottom_up_iteration_loop_20260729.md`
- `ai/reports/t4_first_exact_parity_20260729/`, `t4_bb_exact_vs_myopic_probe_20260728/`

**実測されている数字（doc より）**
- T4後攻 = 閉形式で厳密
- T4先攻 = 厳密解 6ms/root、評価器ノード MAE 0.159
- T3後攻 = その評価器を葉にして厳密比 **相関 0.991 / MAE 0.30**

**演習**
1. 4段の小さなトイゲーム（例：各段2択、終端でランダム報酬）を自作する。
2. そのトイゲームで、(a) 値ブートストラップ (b) 終端までのプレイアウト平均
   の2通りでラベルを作り、段数に対する誤差の伸び方を比較する。
   → doc の主張「プレイアウト・ラベルなら段数に対して誤差が複利で増えない」を自分で確かめる。
3. MAE 0.159 の評価器を葉にして1段解いたら誤差が 0.30 になった。
   **この 0.159 → 0.30 の増え方は妥当か?** 自分のトイゲームの結果と照らして考える。

**卒業判定**
- 「なぜ上から（T0から）作らないのか」を誤差伝播で説明できる
- FL EV の循環（FL EV は最適方策に依存し、最適方策は FL EV に依存する）を説明でき、
  なぜそれが「FLサブゲーム内で閉じる」ので固定点反復で解けるのかを説明できる

### Phase 5 — 教師あり学習の基礎

**演習**

2. **わざとリークを作る**：正解ラベルから作った特徴量を入力に混ぜて学習する。

3. 同じハンドから作った複数のサンプルを train/val に分散させると何が起きるか実験する

### Phase 6 — ニューラルネットの中身

**到達目標**
`ai/models/networks.py` を一行ずつ説明でき、変更したときの影響を**事前に**予測できる。

**中核概念**
- 全結合層 (Linear)、活性化関数 (ReLU)、softmax
- **マスク付き softmax** — `logits.masked_fill(~valid_mask, -inf)` の意味
- Dropout、LayerNorm、残差接続 (residual / skip connection)
- マルチヘッド（1つの胴体から複数の出力）とマルチタスク学習
- 誤差逆伝播 (backpropagation)

**自分のコードのどこを読むか（このフェーズの主教材）**
`ai/models/networks.py`:
- `PolicyNetwork` — `522 → 1024 → 512 → 256 → MAX_ACTIONS`（ReLU + Dropout）
- `forward` の `logits.masked_fill(~valid_mask, float('-inf'))` → `F.softmax`
- `ValueNetwork` — 共有トランク + 4つのヘッド:
  `value_head` / `royalty_head` / `bust_head` / `fl_head`
- `ResidualBlock` — pre-norm 構成（LayerNorm → FC → ReLU → Dropout → FC → Dropout + skip）
- `PolicyNetworkV2` / `ValueNetworkV2` — 残差ブロック×3 を挟んだ改良版
- `select_action` の temperature スケーリング

**演習**
1. `522 → 1024 → 512 → 256 → 27` のパラメータ総数を暗算で出す（bias 込み）。
2. NumPy だけで 2層 MLP を作り、逆伝播を手で実装する。
3. **`masked_fill` を外したらどうなるか予測を紙に書いてから**、実験して確かめる。
4. `ValueNetwork` の4ヘッドが胴体を共有している理由を、
   「royalty と bust と FL は互いに関係する」という観点で説明する。
5. `ResidualBlock` の skip 接続を削除して学習し、何が悪化するか観察する。

**卒業判定**
- 「NNは何を学んでいるのか」を、このプロジェクトの文脈で答えられる
  （→ 答え: **厳密計算の結果の圧縮**。予測ではなく近似）
- MAE 0.159 という数字が「1手あたり平均0.159点ずれる」という意味であること、
  そしてそれが十分か不十分かを、ゲームのスコアスケールと比べて判断できる

### Phase 7 — 模倣と蒸留、そしてその天井

**到達目標**
BC / 蒸留 / DAgger / Expert Iteration の違いと、それぞれの**失敗モード**を説明できる。

**中核概念**
- Behavior Cloning (BC) — 教師の行動をそのまま真似る
- **BCの根本問題**: 分布シフト（真似た方策が到達する局面は、教師データに無い）
- DAgger — 自分で打った局面に教師ラベルを付け直して足す
- Expert Iteration — 探索で強い手を作り、それを学習し、また探索する
- 知識蒸留 / ソフトラベル
- ハードネガティブ、リサンプリング、P99 抽出

**自分のコードのどこを読むか**
- `ai/models/bc_t3/`, `ai/models/bc_t4/`, `ai/models/dagger_bc_v5/`
- `ai/docs/hu_regen_distill_ladder_20260818.md`
- `ai/config/t2_top1hard_ft2_20260619.json`, `t2_top3_residual_ft2_20260618.json`
- `ai/config/t3_balanced400_hardneg_pool_20260608.json`
- `ai/docs/policynet_pruning_pipeline.md`

**演習**
1. `*_hardneg_*` 系の config を読み、「なぜ難しい局面を多めに入れるのか」を
   regret 分布（p99）の観点で説明する。
2. 分布シフトの最小例：教師が絶対に通らない局面をわざと作り、
   BCモデルがそこでどう壊れるか見る。
3. `dagger_bc_v5` と `bc_t3` の設計差分を読み、DAgger が何を解決しているか特定する。

**卒業判定**
- `value_chain_milestones` の
  「方策ネット/BC は Top-1 天井 30〜59%。**値の argmax が方策**」という結論について、
  **擁護と反論の両方**を、根拠つきで述べられる
- 「Top-1 一致率が低い」ことが必ずしも「弱い」を意味しない理由を説明できる
  （→ ヒント: 同点に近い手が複数ある局面では、Top-1 を外しても損失はほぼゼロ）

### Phase 8 — 探索（そしてなぜ主役から外したのか）

**到達目標**
MCTS / PUCT を実装レベルで理解し、このプロジェクトが探索を採用しない判断を
自分で評価できる（同意でも反論でもよいが、根拠が要る）。

**中核概念**
- 多腕バンディット問題、探索と活用のトレードオフ
- UCB1、PUCT（AlphaZero の式）
- progressive widening（行動数が多いときの枝の広げ方）
- visit count → 方策 の変換、temperature

**自分のコードのどこを読むか（主教材）**
`ai/mcts/mcts.py`:
- `MCTSNode.q_value` = `value_sum / visit_count`
- `MCTSNode.ucb_score` = `q + c_puct * prior * sqrt(parent_visits) / (1 + visit_count)`
- `_select` — UCB に従って葉まで降りる、progressive widening 付き
- `_backpropagate` — 訪問回数と値を親へ戻す
- `_get_action_probs` — 訪問回数を確率に変換（temperature 付き）
- `ai/mcts/multi_turn_mcts.py`, `ofc_mcts.py` — OFC 特化版

**演習**
1. `ucb_score` の式を紙で追い、`visit_count` が増えると探索項がどう減るか手で計算する。
2. `c_puct` を 0.1 / 1.5 / 10 に変えたときの挙動を**予測してから**実験する。
3. じゃんけんのような小さな問題で UCB1 を自分で実装し、後悔 (regret) が
   `O(log n)` で増えることを確認する。
4. **評価器にバイアスを入れて MCTS を回す**（Phase 2 の演習3の再演）。
   シミュレーション数を増やすと、誤りは減るか、増えるか？

**卒業判定**
- 「評価が誤っていれば探索は最適に誤る」を式で説明できる
  （→ MCTS は `V̂` の argmax に収束する。`V̂ ≠ V` なら、収束先が間違っている）
- 20,000 シミュレーション実験の結論に対し、自分の立場を根拠つきで述べられる

### Phase 9 — 後悔最小化と均衡

**到達目標**
CFR が何を保証していて、**何を保証していないか**を説明できる。

**中核概念**
- ナッシュ均衡、ミニマックス
- exploitability（搾取可能性）— 「この方策は最大でどれだけ負けるか」
- regret matching、CFR、CFR+、MCCFR（外部サンプリング / 結果サンプリング）
- 抽象化 (abstraction) — 状態をまとめて計算量を下げる、その代償

**自分のコードのどこを読むか**
- `ai/cfr/ofc_cfr.py`（23KB。本体）
- `ai/cfr/abstraction.py` — 状態の抽象化
- `ai/cfr/game_state.py`, `train_cfr.py`, `evaluate_cfr.py`

**演習**
1. **じゃんけんに CFR を実装する**（30行程度）。regret が 0 に収束し、
   平均戦略が 1/3, 1/3, 1/3 になるのを見る。**これが CFR 理解の最短ルート。**
2. Kuhn poker（3枚札の最小ポーカー）に CFR を実装し、既知の均衡と一致するか確認する。
3. `abstraction.py` を読み、どんな情報を捨てているか列挙する。捨てた情報が
   効いてくる局面を1つ考える。

**卒業判定**
- CFR が保証するのは「平均戦略が均衡に収束する」であって
  「毎回の戦略が最適」ではないことを説明できる
- exploitability probe が何を測るのか、そして
  「捨て札尤度の再重み付けの必要性を exploitability probe で測ってから決める」
  という doc の方針の意味を説明できる

### Phase 10 — 強化学習とセッションEV

**到達目標**
`ai/docs/rl_environment_spec.md` を、自分で一から書き直せる。

**中核概念**
- MDP / POMDP、状態・行動・報酬・遷移・割引
- 価値関数 `V(s)` / 行動価値 `Q(s,a)` / advantage `A(s,a) = Q - V`
- 方策勾配、PPO、advantage-weighted imitation
- self-play、population-based training
- **報酬設計** — 何を最大化するかの選択が、方策を決める

**自分のコードのどこを読むか**
- `ai/docs/rl_environment_spec.md` ← 主教材
- `ai/docs/bottomup_to_rl_roadmap.md`
- `ai/models/ppo_v1/`, `ppo_v2/`, `ppo_selfplay/`
- `ai/calc_fl_ev.py`, `ai/config/fl_ev.json`

**このフェーズの核心：1ハンドEV ≠ セッションEV**

`rl_environment_spec.md` によれば、真の目標は
`session_return = final_chips[seat] - 200` です。1ハンドの EV ではありません。
これが効いてくるのは次のような場面です。

- **スコアキャップ**: 相手が残り5点なら、20点勝つ手も実際には5点しか取れない
- **40点差終了ルール**: 大きくリードしているとき、ハンドを終わらせること自体に価値がある
- **FL がセッションを延長する**: 40点差でも FL 中はセッションが続く

**演習**
1. 「1ハンドEVでは A の手が良いが、セッションEVでは B の手が良い」という
   具体例を**自分で3つ作る**（キャップ、40点差、FL継続でそれぞれ1つ）。
2. `fl_ev.json` を読み、FL EV が固定値として使われている箇所を特定する。
3. FL EV の固定点反復（M-B → M-C）が、なぜ2〜3周で収束すると見積もられているか考える。

**卒業判定**
- 「FL EV は最適方策に依存し、最適方策は FL EV に依存する」循環を説明でき、
  なぜ **FLサブゲーム内で閉じる**（通常vs通常の方策は FL EV を消費するだけで定義に入らない）
  ので固定点反復が使えるのかを説明できる
- 報酬をセッションEVにすると、価値関数が学ぶべきものが何個増えるか列挙できる

### Phase 11 — 実験科学（ここが一番差がつく）

**到達目標**
自分の改善案を、**反証可能な形**で提案できる。

**中核概念**
- regret 分布: mean / median / p90 / **p99** / max、zero-regret 率、low-regret 率
- Top-1 / Top-3 一致率 — そしてその限界
- TV距離（全変動距離）による方策比較
- 較正 (calibration) — 予測した確率が実際の頻度と合っているか
- ペア比較と共通乱数 — 同じ乱数で2つの方策を戦わせて分散を消す
- シード間 drift
- **事前棄却条件 (pre-registered kill criteria)**
- ablation study — 要素を1つずつ抜いて寄与を測る

**自分のコードのどこを読むか**
- `ai/config/promotion_gate_v1.json`, `promotion_gate_v2.json` ← **主教材**
- `ablation_study.py`, `ai/analyze_p99.py`, `ai/deep_eval_inspect.py`
- `ai/reports/` 以下の各レポート
- `ai/docs/bottom_up_iteration_loop_20260729.md` の収束判定表:
  方策TV距離 平均<0.02 / 最大<0.10、Top-1一致率 >95%、
  厳密解に対する regret 平均 <0.01点/手

**このプロジェクトが既に持っている「良い習慣」**

`value_chain_milestones_20260731.md` には**段ごとの棄却条件が事前宣言**されています。

> 1. T3先攻の行動一致率がサンプル厳密解に対して急落
> 2. プレイアウト・ラベルのT2評価器が厳密スポット検査で系統的バイアス
> 3. pass 2のon-policy分布でpass 1評価器が崩壊
>
> いずれかが出た段だけ、厳密教師を深くする方向に切替える。
> **周回数を増やして解決しようとしない。**

これは研究として非常に質が高いやり方です。あなたが提案をするときも、
必ずこの形式（何を測るか + どうなったら捨てるか）で出してください。

**演習**
1. `promotion_gate_v2.json` の各条件を1つずつ取り上げ、
   「この条件が無かったら、どんな悪いモデルが通ってしまうか」を書く。
2. 平均 regret は同じだが p99 regret が大きく違う2つのモデルを想像し、
   実戦でどちらが強いか、理由つきで論じる。
3. 自分の改善案を1つ考え、以下の形式で書く:
   - 仮説 / 測る指標 / ベースライン / 必要サンプル数（Phase 2 の SE で計算）/ **事前棄却条件**

**卒業判定**
- 「平均だけ見てはいけない」理由を、OFC のスコア分布の性質から説明できる
- 新しい提案を、必ず「測る指標 + 事前棄却条件」とセットで出せる

## 6. LLM との付き合い方（学習中の最重要ルール）

いまは「LLMに全部任せる」状態です。ここから抜けるには、**質問の型を変える**のが一番速い。

### 変えるべき質問

| ✕ 今までの質問 | ○ これからの質問 |
|---|---|
| 「これを実装して」 | 「この設計の**失敗モードを3つ**挙げて。それぞれ何を測れば検出できる?」 |
| 「どうすれば強くなる?」 | 「この改善の**期待効果を点数で**見積もって。根拠になる実測値はどれ?」 |
| 「これでいい?」 | 「この案を**却下すべき条件**を先に書いて」 |
| 「エラーを直して」 | 「なぜこのエラーが出たのか、原因の仮説を3つ、検証順に並べて」 |

### 守るべき習慣

1. **数字を必ず要求する。** 「改善します」ではなく「p99 regret が 0.8 → 0.5 になるはず」。
2. **事前棄却条件を先に書かせる。** 走らせる前に「どうなったら捨てるか」を決める。
3. **LLM の主張を自分のリポジトリの実測値と突き合わせる。**
   このプロジェクトには `ai/reports/` に大量の実測がある。矛盾したら実測が勝つ。
4. **週に1つ、過去のLLM提案の誤りを見つける。** これが上達の一番の指標です。
5. **分からない言葉を1つも流さない。** 「良い感じに」「最適化して」は理解していない印。
