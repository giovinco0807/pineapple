## 1. 期待値とは何か

期待値は「平均して、いくらになるか」です。

```
E[X] = Σ  p(x) · x
       x
```

サイコロなら `(1+2+3+4+5+6)/6 = 3.5`。3.5 の目は存在しませんが、
**何度も振れば平均は 3.5 に近づく**。これが大数の法則です。

### 期待値の線形性（これが全ての土台）

```
E[aX + bY] = a·E[X] + b·E[Y]
```

X と Y が独立でなくても成り立ちます。これのおかげで

> 盤面全体の期待値 = top の期待値 + middle の期待値 + bottom の期待値 + FLの期待値

のように**分解して計算できる**。`ai/models/networks.py` の `ValueNetwork` が
`value_head` / `royalty_head` / `bust_head` / `fl_head` の 4 つに分かれているのは、
この線形性を利用した設計です。

まず `python lesson01.py` を実行して、**Part 1** の出力を見てください。

## 2. OFC の局面を期待値で評価する

**Part 2** が今日の中心です。局面はこう設定しました。

> 自分の bottom 行に ♥ が 4 枚、残り 1 スロット。
> 次のターンに 3 枚配られる。♥ かジョーカーが 1 枚でもあればフラッシュ完成、+4 点。
> 未確認カードは 44 枚、うち ♥ が 9 枚 + ジョーカー 2 枚 = **アウツ 11 枚**。

厳密計算は組合せだけで出ます。

```
完成確率 = 1 - （アウツを1枚も引かない確率）
        = 1 - C(33,3) / C(44,3)
        = 1 - 5456 / 13244
        = 0.5880

期待値 = 0.5880 × 4 = 2.3522 点
```

`+4` という数字は、あなたのリポジトリの
`ai/engine/game_engine.py` の `get_bottom_royalty()` から取っています。

```python
def get_bottom_royalty(cards):
    ...
    if cat == 5: return 4    # Flush
    if cat == 4: return 2    # Straight
```

**この計算が、あなたのプロジェクトの全ての土台です。**
T0 の 232 手も、T3 の 3 手も、やっていることは
「各手について、この先起こりうる全てを平均したスコア」を出して、一番高いものを選ぶ、
それだけです。違うのは、**規模**と**相手がいること**だけ。

## 3. モンテカルロ：厳密に計算できないときの代用

上の問題は組合せで厳密に解けました。でも T0 の局面で
「この 5 枚の配置の価値」を厳密に出そうとすると、残りのゲーム全体を
展開しなければならず、現実的な時間では終わりません。

そこで**実際にランダムに何度も配って、平均する**。これがモンテカルロです。

```python
def mc_ev(n):
    hits = 0
    for _ in range(n):
        if min(random.sample(range(44), 3)) < 11:   # アウツを引いたか
            hits += 1
    return 4 * hits / n
```

これが `bench_pimc_500_samples.py` や `ai/mcts/rollout_evaluator.py` が
やっていることの、いちばん単純な形です。

## 4. サンプル数と誤差 — `1/√n`

**Part 3** の出力を見てください。

| n | 実測SE | 理論SE = σ/√n |
|---|---|---|
| 10 | 0.603 | 0.623 |
| 100 | 0.205 | 0.197 |
| 1,000 | 0.063 | 0.062 |
| 10,000 | 0.016 | 0.020 |

標準誤差は

```
SE = σ / √n
```

に従います。ここから出てくる、**実務上いちばん重要な帰結**：

> **誤差を 1/2 にするには サンプル 4 倍。1/10 にするには 100 倍。**

`gcp_*.sh` のスクリプト群、64 コアの VM、スポットインスタンスのフリート —
あれらは全部この `√n` と戦うために存在しています。

---

## 5. 今日の核心 — バイアスは消えない

**Part 4** が今日の結論です。

推定の誤差は 2 つの成分に分解できます。

```
誤差 = バイアス（体系的なズレ） + 分散（ばらつき）
```

- **分散** は n を増やせば `1/√n` で消える
- **バイアス** は n をいくら増やしても**まったく消えない**

Part 4 の出力を再掲します。

| n | 正しい評価器の誤差 | 0.3 だけ偏った評価器の誤差 |
|---|---|---|
| 100 | 0.152 | 0.321 |
| 1,000 | 0.047 | 0.306 |
| 10,000 | 0.019 | 0.304 |
| 100,000 | 0.004 | **0.301** |

右の列は 0.3 で張り付いたまま動きません。

### これが意味すること

`ai/docs/value_chain_milestones_20260731.md` にはこう書かれています。

> - 評価の誤りは探索量で救えない(20,000シミュレーション実験)
> - MCTS/PUCT: 評価が誤っていれば探索は最適に誤る

**あなたはいま、この主張を自分で再現しました。**
探索（MCTS）は「評価器の値の argmax」に収束します。評価器が 0.3 ずれているなら、
探索は「0.3 ずれた値の argmax」に**正確に**収束する。より速く、より確実に、間違える。

### 明日から使える判断基準

LLM が「精度が足りないのでサンプル数を増やしましょう」と言ってきたとき、
返す質問は 1 つです。

> **「その誤差は、分散由来ですか、バイアス由来ですか。どうやって切り分けましたか?」**

分散由来ならサンプルを増やすのが正解。バイアス由来なら、いくら GCP を回しても
1 円も報われません。**この質問だけで、無駄な計算コストの多くを止められます。**
