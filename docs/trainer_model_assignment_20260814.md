## 3. この割り当てで何が起きるか

### 3.1 `t0first_model_v1.bin` が使われなくなる

通常T0先攻も対FL T0も `vsfl_t0_v2.vfl1` になるため、`t0first_model_v1.bin`（`07301034502d`）は
どちらの席からも外れる。このファイルは 2026-08-06 のオーナー裁定でvs-FLの代用として使われていた
当のもので、**代用が本物に置き換わる**という筋は通っている。

参考（実測1ハンドのみ）: ハンド#2のT0配札 8♠4♣2♠10♠5♣ に対し、`vsfl_t0_v2` の1位と
通常T0モデル（`model_scores`）の1位は**一致**した（どちらも 中:4♣5♣ 下:8♠2♠10♠）。
一方で教師探索は同じ手を84位/232（2/4サンプル）・232位/232（1サンプル）と評価していた。
1ハンドの一致は根拠として弱いので、採用の可否は別途の比較で決めること。

### 3.2 `fast_*` イメージの役割が二重になる

`fast_t0_second_v1` / `fast_t1_first_v1` / `fast_t1_second_v1` は**今もピンされている**が、
それは「教師探索が内部で相手の応手を速く打つための蒸留版」という役割で、
ランキングを出す当のモデルではない。今回の指示はこの3つを**採点そのもの**に使うというもの。
同じバイト列に2つの役割を持たせることになるので、どちらの用途で読まれているかを
ログとUIで区別できるようにしておくこと（現在は両方とも "learned" としか出ない）。

`fast_t2_first_v1` / `fast_t2_second_v1` は今回の割り当てに現れない。T2は本体モデルのままなので、
この2つは**応手用としてのみ**残る。

### 3.3 本体モデルは外せない（教師探索の継続として必要）

ピン表は2つの役目を兼ねている:

1. **その街を採点するモデル**（今回の指示の対象）
2. **教師探索が下流の街を読むときの継続モデル**

`t0_model_v1` / `t1_model_v1` / `t1first_model_v1` を採点から外しても、**ピン表からは外せない**。
T0先行の探索は下流7〜8個の学習済み評価器が揃っていないとエンジンが街ごと拒否するため
（`trainer/README.md` の「ピンの依存関係」）。採点方法として教師探索を選べる限り、
これらは継続として残す。

## 5. 「改修が必要かも」の中身 — 3案とその意味

オーナーが T0後攻（`fast_t0_second_v1`）と T1両席（`fast_t1_first_v1` / `fast_t1_second_v1`）に
付した注記。この3つは**蒸留クローン**であり、そこが注記の理由に直結する。

### 5.1 まず「蒸留」とは何か（この project での定義）

`docs/hu_joint_policy_t0_flev_verification_20260803.md:98-110` が定義と実測を持っている:

> Teacher rollouts spend ~92% of their time encoding features for nested model
> decisions (profiled). Distilled clones — coarse features (histogram caps
> 4000→400, joint draws 512→64), tiny nets **trained to imitate the full model's
> choices**, used *only inside rollouts* (decide/root paths stay full precision)
> — recover most of it.

つまり `fast_*` は「本体モデルの**選択を真似る**ように学習した小さいネット」で、
特徴量はわざと粗くしてある（ヒストグラム上限 4000→400、joint draws 512→64）。
目的は速度で、強さではない。実測は同ドキュメントの表:

| クローン | 本体との一致 top-1 / top-3 | 効果 |
|---|---|---|
| fast_t1_first / fast_t1_second | **70.4 / 93.7**、**72.0 / 94.4** | `evaluate_t1` が 2.8倍速 |
| fast_t0_second | **70.5 / 93.7** | T0先行の評価 120.8秒 → 22.8秒（**5.31倍**） |

**ここが注記の核心**: 設計上これらは *only inside rollouts* で使うものとされ、
**decide/root パスは全精度のまま**と明記されている。今回の割り当ては、その除外されていた
root パス（＝採点そのもの）にクローンを置く。本体との top-1 一致は約70%なので、
**10局面に3局面は本体と違う手を1位にする**ことになる。

### 5.2 3案が直すものは別々で、順番がある

| 案 | 何を直すか | 直らないもの |
|---|---|---|
| **再蒸留** | クローンと**本体との一致率**（70% → もっと上へ） | 本体そのものの質。ラベルの定数・粒子数はそのまま |
| **9.6でのリラベル** | ラベルの**FL定数**（T1・T0後攻は10.227、T0先攻は9.109のまま） | クローン。本体を再学習しても、クローンは古い本体を真似たまま |
| **粒子数引き上げ** | ラベルの**ノイズ**（T1・T0は256粒子。T2は2,048、T3は1,024） | 同上 |

依存関係は一方向:

```
ラベル再生成（9.6 / 粒子数↑） → 本体モデル再学習 → クローン再蒸留
```

- クローンを採点に使うなら、**リラベルや粒子数引き上げだけでは効かない**。
  本体を作り直したあとに再蒸留しないと、クローンは古い本体を真似たままになる
- 逆に**再蒸留だけ**なら、今の本体との一致率を上げるだけで済む。ラベル生成は不要なので
  フリートも要らない（クローンの学習は本体の出力を教師にした模倣学習）

### 5.3 各案のコスト（記録にある実測値）

**再蒸留**: 粗くしてある特徴量（4000→400、512→64）を戻す、模倣データを増やす、ネットを大きくする、
のいずれか。速度と一致率の取引で、どこまで戻すかは「rollout内で使う」前提が外れた今、
測り直す必要がある。既存クローンは採用前に argmax/EV ゲートを通しているので
（"Every clone passes an argmax/EV gate against the full teacher before adoption"）、
同じゲートを**採点用の基準に置き換えて**再実行するのが筋。フリート不要。

**9.6でのリラベル**: `docs/trainer_ranking_quality_20260808.md:305` に
「the T1 relabel is currently budgeted at 10–20 fleet hours」。T0は
`docs/hu_m7_cascade_20260806.md:63-64` が「relabel DEFERRED per owner」として明示的に見送っている。

**粒子数引き上げ**: `docs/hu_m7_cascade_20260806.md:1249-1268` に測定済み。
T1ペアで 3,881 core-s/root ＝ **1.08 core-h/root**、1,000 root の確認プローブで
**約2.3フリート時間**（464コア）、悲観ケース（2倍膨張）で4.1時間。
なお同文書はT1について「ラベルのSEは draw 支配であって N 支配ではない」とも記録しており
（`docs/hu_m11_vsfl_opponent_model_20260805.md:800`）、粒子数だけ上げても効かない可能性がある。

### 5.4 この割り当てに限って言えば

採点に使うのが目的なら、**最小の一手は再蒸留**（フリート不要、直す対象が「本体との不一致30%」そのもの）。
定数世代を揃えたいなら リラベル→再学習→再蒸留 の順に3工程が要る。
どれを指した注記なのかは未確認。
