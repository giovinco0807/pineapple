# OFC トレーナー（レギュラー）

https://ofc.olegsolvers.com/ を参考にした、レギュラーOFC Pineapple（ヘッズアップ・Jokerなし）のローカル学習用Webアプリ。

## 機能

- **トレーニング**: AI相手に1ハンドずつプレイ。各判断を全候補のEVランキングで採点。
  - 最善手なら自動続行 / 最善手を強制 / 候補1つの時はスキップ
  - しきい値以上のEVロスは自動でミス記録
- **エディタ**: 任意の局面（自分・相手の盤面、配札、死札）を作って候補EVランキングを表示
- **ミス復習**: 記録されたミスを同じ局面でリトライ
- **アカウント**: ヘッダーのセレクタで履歴を切り替え。ハンド履歴・ミス・統計はすべてアカウント単位。

## アカウント

ローカル専用ツールなのでログインではなく「名前付きの履歴バケツ」。

- ヘッダーの `＋` で作成、セレクタで切り替え、`🗑` でそのアカウントの履歴を全削除
- 選択中のIDはブラウザの localStorage に保存され、全APIに `X-Account-Id` ヘッダーで乗る
- ヘッダーが無い／未知のIDの場合は `default` アカウントにフォールバック（認証ではなく識別）
- アカウント導入前のDBは起動時に自動マイグレーションされ、既存の行は `default` に紐づく
- ハンドは**開始時**のアカウントに記録される（途中で切り替えても記録先は変わらない）
- `default` アカウントは削除不可

## 起動

```powershell
cd regular-ofc-pineapple
python -m uvicorn trainer.app:app --host 127.0.0.1 --port 8093
```

ブラウザで http://127.0.0.1:8093 を開く。

## 構成

- `app.py` — FastAPI（認証なし・ローカル用）
- `game.py` — トレーニングセッション（配札、AI対戦相手、バックグラウンドEV解析、採点）
- `evaluator.py` — ストリート別評価器（候補列挙 + EVランキング）
- `fl_ev.py` — FL EV定数を `configs/` から読む（ハードコード禁止）
- `store.py` — SQLite（アカウント・ミス・ハンド履歴、`trainer/data/trainer.sqlite3`）
  - `GET /api/accounts` / `POST /api/accounts` / `DELETE /api/accounts/{id}`
  - `GET /api/history?limit=N` — アカウントのハンド履歴
- `static/` — フロントエンド（素のJS・日本語UI）

## 評価の仕組み

各ストリートの全合法手を列挙し、EVで降順ランキング。ユーザーの手の順位とベストとのEV差で採点する。

**全ストリート・両席が m3 エンジン経路**（2026-08-07、m7v5 パッケージのピン14個を投入）。
MC は fallback としてのみ残る。実測（precision=fast、全候補ランキング）:

| ストリート | 評価器 | 候補数 | 先行 | 後攻 |
|-----------|--------|-------|------|------|
| T0 | `rust:t0` | 232 | 20.5秒 | 5.0秒 |
| T1 | `rust:t1` | 24〜27 | 0.45秒 | 0.26秒 |
| T2 | `rust:t2` | 9〜24 | 0.12秒 | 0.09秒 |
| T3 | `rust:t3` | 9〜21 | 0.03秒 | 0.02秒 |
| T4 | `rust:t4_exact` | 3〜6 | 即時 | 即時 |

- エンジン: `target/release/ofc_hu_m3_engine.dll`（**`.windows-target` の古いDLLはT1/T2非対応なので使わない**）
- 学習済み重み: `rust/hu_m3_engine/tests/fixtures/*.bin`（m7v5パッケージと同一SHA）

**ピンの依存関係**（エンジンは下流が揃わない街を拒否する）:

- T1先行 → `learned_t1_second` が必須（全ロールアウトが相手のT1後攻応手で始まる）
- T0後攻 → 下流7個、T0先行 → さらに `learned_t0_second` を足して8個
- これが「T0とT1先行がMCに落ちていた」理由。評価器の未実装ではなく**ピン不足**だった

**`fast_*`（蒸留版）を5個入れている理由**: 速度のためで、強さのためではない。
入れないとT0先行が**292秒**かかり、対話的に使えない（実測）。入れると20.5秒＝14倍速。
エンジンはこれらを使う評価器を `learned_fast` と報告する。T3/T4に蒸留版は存在せず常に全精度。

**FL定数の世代差**: T4(v6)/T3(v3,v2) は 9.6 でリラベル済み、T2以下は旧定数(10.227)のまま。
M7 cascade が T2 で進行中のため。DLL自体は 9.6 でビルド済み（ゴールデンピン24件で検証）。

## 「モデルを使う」と「教師で採点する」は別物

これを混同すると桁で見誤る。同じT0先行の局面で:

| 操作 | エンジンのkind | 時間 | 何をしているか |
|------|---------------|------|---------------|
| モデルが打つ | `decide` | **0.09秒** | ルート扇へのforward pass。`evaluator: learned` |
| 教師が採点する | `t0` | **19.9秒** | 下の全ストリートを探索。このモデルのラベルを作った当のもの |

220倍差。トレーナーは**両方**要る — 採点には全候補のEVランキングが要るので教師、
AI対戦相手は1手あればいいので `decide`。

**AI対戦相手は `decide` を使う**（`game.py::_opponent_move`）。ここをランキングにしていた頃は、
後攻で1ハンド始めるたびに**19.5秒**、誰も読まないランキングをAIのために回して待たされていた。
`decide` にして0.2秒。エンジンが拒否した場合はランキング経路にフォールバックするので、
ピンが揃っていない環境でも対戦相手は動く。

## 実測レイテンシ（precision=fast、1ハンドの立ち上がり）

| | 先行 | 後攻 |
|---|------|------|
| 配札→自分が打てるまで | 0.1秒 | 0.2秒 |
| AIの応手 | 0.7秒 | 0.2秒 |
| 自分のT0の採点が出るまで | 18.5秒 | 6.3秒 |

**T0の採点だけは重い**。232ルート×最深の木という形に由来する固有コストで、設定ミスではない。
枝刈り機構（`prefilter_samples` / `race_schedule`）はどちらも**粒子数**を削るもので、
こちらは既に最小の1粒子なので効かない。

採点はカードが配られた瞬間からバックグラウンドで走る。5枚を置く操作をしている間に
進むので実用上はかなり隠れるが、**即座に確定すると待たされる**。T1以降は全て1秒未満。

## AI対戦相手

エンジンの `decide` が返す手をそのままプレイ（＝学習済みモデルの手）。全ストリートがモデル経路になったため、
**本番webappより強い**（本番の `assembly.json` は T0/T1/T2先攻 を `python_policy` に流しており、
T0/T1の学習済みモデルを1つも使っていない）。本番AIの挙動を再現したい場合はここが乖離点。

## FL（ファンタジーランド）

v1ではFL突入を検知して固定EV（+9.6、`configs/fl_ev_regular_v4_selfplay.json`）を結果に表示するのみ。
定数は `trainer/fl_ev.py` がこのconfigから読むので、configが更新されれば自動で追従する。

**解消済み（2026-08-07）**: かつてDLLのビルド(08-05 23:49)が `infoset.rs` の 9.6 化(08-06 19:59)より
古く、エンジンだけ旧定数で動いていた。`cargo build --release -p ofc_hu_m3_engine` で再ビルド済み。
検証は `t0_pruning_safety` / `t0_stage_two_racing` の24件（`a_raced_run_is_deterministic_and_pinned`
含む）で、これらのゴールデンピンは 08-06 に 9.6 用へ再ピンされたもの。全件パス。
DLLのバイト列から定数を直接読む方法は使えない（インライン化されていて f64 リテラルとして現れない）
ため、挙動での検証がここでの唯一の手段。

なお fleet の Linux `.so`（`e17aa39f…`）とはバイト一致しない。プラットフォームが違うため当然で、
担保できるのは「同一ソース・同一定数からのビルドでゴールデンピンが一致」まで。
旧DLLは `target/release/ofc_hu_m3_engine.dll.pre96-backup` に退避してある。
FLハンド自体のプレイ・採点は未実装（`regular_fl_solver.exe --solve` で拡張可能）。
